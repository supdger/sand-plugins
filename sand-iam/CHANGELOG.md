# SandIAM 变更日志

本文件只记录能够由当前公开源码、迁移和包契约复核的发行变化，不补写无法从权威来源确认的
历史版本内容。日期标记为“待发布”的条目仍是候选，不代表已经上传、部署或公开发布。

## 0.7.3（待发布）

### 安全与一致性

- 身份角色、身份用户类型与策略目标增加同一应用的组合外键，数据库直接拒绝跨应用关联；
  管理端关系写入同步保存由身份解析出的 `application_id`。
- 策略版本、回滚来源和已发布版本指针增加同策略、同应用的组合归属约束，并补齐版本号、
  JSON 对象快照和小写 SHA-256 摘要检查。
- 策略动作列从 `varchar(64)` 扩展为 `varchar(96)`，与应用动作和管理 API 的公开长度一致。
- 审计清除保留“归档副本”语义；获得主体策略、部署开关和确认摘要共同授权后，清除过程使用
  底层表物理删除到期热日志及归档正文，并覆盖旧版本错误软删除后隐藏的归档记录。

### 兼容与升级

- 正常升级路径为 `0.7.2 → 0.7.3`：先精确核验 `001–040` 的 41 条迁移账本、账本结构及
  修订 039/040 的目标结构，再只执行 `041_authorization_scope_integrity.pgsql`。
- 041 在固定锁顺序下先检查全部存量归属冲突；发现跨应用授权、跨策略发布/回滚指针或非法
  版本快照时关闭失败并回滚，不删除、换绑或猜测修复业务数据。
- 已发布的 `001–040` 保持字节不变；成功终态为 42 条迁移账本记录且最大修订号为 41。

## 0.7.2（待发布）

### 运行与配置

- `release` 配置预检现在要求机器上下文、人类认证、MFA、OIDC issuer、pairwise subject 和联合身份所需的
  六项基础值；空环境关闭失败，并且只报告配置键和错误码，不回显秘密值。
- 随包 Composer 根包与 `sand/sand-iam` 的生成元数据、离线构建参数、构建摘要和公开版本说明统一为
  `0.7.2`，避免安装包仍把当前候选识别为 `0.7.1`。

### 功能与体验

- 目录同步增加运行所有权和遗留 `running` 任务恢复：同一连接器由固定 PostgreSQL 会话锁约束，
  连接替换或丢失后旧运行者不能继续写入；恢复开关默认关闭，升级时须先排空旧版本运行者。
- Kerberos/SPNEGO 增加内置 PECL GSSAPI 验证器和直接 TLS 上下文解析器，要求部署方提供受控
  keytab 引用、固定服务证书、通道绑定、mutual/replay 标志和持久重放缓存。
- PHP、TypeScript 和 Dart SDK 补齐注册验证、邀请接受、密码恢复、MFA、Passkey、联合身份解绑、
  验证码配置和敏感操作二次验证调用；默认传输拒绝携带凭证跟随重定向。
- 自助门户接入按应用加载的验证码配置和 Turnstile 挑战，应用切换、失败或过期时丢弃旧令牌，
  不在持久存储中保留验证码响应。
- 管理端补齐大数据量下的远程应用搜索、分页和迟到响应保护，并为同步保护、Webhook、告警、
  审计保留、OIDC 登出恢复和策略版本提供明确的失败恢复入口。

### 安全与一致性

- 账户、管理委派、身份关系、策略发布、MFA、同步配置和运行终态等关联写入统一检查保存结果，
  业务事实与成功审计在同一事务内提交，失败时回滚并允许使用同一业务请求重试。
- 机器上下文在签发、验证和调用前重新核对应用、环境、调用身份、凭证、服务授权、受众、配额、
  网络及数据分级状态；停用、撤销和事实变化后关闭失败。
- 机器调用示例严格拒绝带尾随换行或超出长度边界的文档 ID、请求 ID 和幂等键，验证失败时不进入
  业务存储；失败审计不记录凭证明文或完整上下文。

### 兼容与升级

- 正常升级路径为 `0.7.1 → 0.7.2`：先精确核验 `001–038` 的迁移账本、账本结构、
  `sand_iam_service_grant.data_class` 原始结构以及修订 038 的保留索引，再只执行
  `039_service_grant_nullable_data_class.pgsql` 和 `040_passkey_auth_challenge_identity.pgsql`。
- `039` 解除 `data_class` 的非空约束并保留 `varchar(32)` 类型、`internal` 默认值、现有数据及
  检查约束，使持久化结构与公开接口中“空值表示授权不附加数据分级限制”的语义一致。
- `040` 允许匿名 Passkey 挑战在校验成功后绑定解析出的身份；其他认证挑战仍必须始终绑定身份，
  使登录成功审计、会话和验收清理能引用同一真实 challenge。迁移核对 PostgreSQL 约束定义时
  先移除类型转换再压缩空白，避免 `::text OR identity_id ...` 被合并成错误的类型名。
- fresh install 直接创建相同的列和挑战约束；升级载荷不会重放 001–038，也不会修改已发布迁移文件。

## 0.7.1（待发布）

### 兼容与升级

- 正常升级路径为 `0.7.0 → 0.7.1`：先精确核验 `001–037` 的迁移账本身份、账本结构和已完成的
  86 张 `sand_iam_*` 表，再只执行已发布且字节不变的 `038_auth_rate_limit_retention.pgsql`。
  成功终态为 86 张表、39 条账本记录且最大修订号为 38。
- `038` 的字节与其账本 `package_version=0.7.0` 均保持不变；本版本不创建虚构的 `039`，也不接受
  不完整账本、未知条目、冲突身份或伪造失败状态。
- 正常 0.7.1 包不再携带或生成失败升级恢复描述器。保留的 0.7.0 描述器只属于历史
  `0.6.0 → 0.7.0` 的 `ledger_absent` 恢复证据，不表示 0.7.1 支持从 0.6.0 直接升级。

### 发布治理

- 增加 Apache-2.0 `LICENSE`、`NOTICE`、唯一 DCO 签署流程以及 GitHub private advisory
  漏洞报告入口；这些公开治理材料与 SBOM 一并进入正常安装包。

## 0.7.0（待发布）

### 兼容与升级

- 插件支持 SandAdmin `6.x`，数据库仅支持 PostgreSQL。
- fresh install 使用根与插件镜像一致的 `001–038` 迁移集合；当前正式声明的历史升级入口为
  `0.6.0 → 0.7.0`，只执行 `033–038`。不得跨过未声明版本或手工改写迁移账本。
- 已发布的 `021_admin_permission_catalog.pgsql` 保持不可变；后续修复继续追加新迁移。
- 当前候选不声明公开接口、稳定错误码或组织/应用/环境隔离语义的不兼容变更。未来若需要
  不兼容变更，必须先发布版本、迁移和 API/SDK/页面同步说明。

### 新增

- `033_identity_group_role.pgsql`：身份、用户组与角色关系。
- `034_identity_group_role_permission_catalog.pgsql`：三项用户组角色管理权限目录，不自动授予既有角色。
- `035_schema_migration_ledger.pgsql`：带结构指纹前置校验的 SandIAM 迁移账本。
- `036_acceptance_fixture_support.pgsql`：发布验收支持；验收接口在正常运行配置中默认关闭。
- `037_initialization_draft.pgsql`：初始化草稿与修订记录。
- `038_auth_rate_limit_retention.pgsql`：为认证限流过期状态的有界清理增加 `(window_start, id)` 访问路径。
- 增加默认关闭的运维状态保留 worker：按 30–3650 天策略分批删除过期 `succeeded` 幂等记录，并按
  1–168 小时策略分批删除过期认证限流窗口；pending 幂等记录与审计日志不进入该清理范围。
- 增加 OIDC 后通道登出 dead 投递恢复：保留原失败证据，重新签发短时 logout token，并以确定性
  后继事件收敛重复和并发恢复；列表、响应和审计均不暴露 token 或密文。
- 管理 OpenAPI 契约提升为 `0.13.0-candidate`，为上述恢复操作公开精确分页参数、请求/响应 DTO、
  稳定错误码及 404/503 响应；运行端点与既有隔离语义保持兼容。

### 发布材料

- 增加中文安装升级、首次接入、管理员、应用用户、安全、备份恢复、排障及发布包校验说明。
- 增加 CycloneDX 1.6 SBOM、第三方许可告知、贡献说明和漏洞报告指南。
- 候选构建统一排除测试、内部任务材料、本机路径、秘密、缓存和非运行时构建目录；TypeScript
  SDK 的受控 ESM `dist` 是唯一明确例外。
- 增加可复现 ZIP、包外 Ed25519 证明及逐条目校验流程。正式签名仅可绑定干净、已提交、
  已获批许可证且通过全部发布门禁的 `release/unsigned` 候选。

### 尚未完成的发布条件

当前源码仍是未发布候选。正式安装/升级/卸载、七条真实业务链、四角色页面、标准协议对端、
非 AI 业务应用与机器服务、并发/备份恢复、同候选 24 小时稳定性、Casdoor 独立对照、最终许可
及签名必须全部形成当前证据后，才能移除“待发布”状态。

## 0.6.0（历史基线）

当前仓库只把 `0.6.0` 作为受支持升级来源和已发布迁移不可变基线。本文件不重建其原始发行说明；
需要审计历史行为时，应使用当时发布包、标签及其原始校验值，不能从 0.7.0 候选反推。

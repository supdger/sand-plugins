# SandIAM 变更日志

本文件只记录能够由当前公开源码、迁移和包契约复核的发行变化，不补写无法从权威来源确认的
历史版本内容。日期标记为“待发布”的条目仍是候选，不代表已经上传、部署或公开发布。

## 0.7.1（待发布）

### 兼容与升级

- 正常升级路径为 `0.7.0 → 0.7.1`：先精确核验 `001–037` 的迁移账本身份、账本结构和已完成的
  86 张 `sand_iam_*` 表，再只执行已发布且字节不变的 `038_auth_rate_limit_retention.pgsql`。
  成功终态为 86 张表、39 条账本记录且最大修订号为 38。
- `038` 的字节与其账本 `package_version=0.7.0` 均保持不变；本版本不创建虚构的 `039`，也不接受
  不完整账本、未知条目、冲突身份或伪造失败状态。
- 正常 0.7.1 包不再携带或生成失败升级恢复描述器。保留的 0.7.0 描述器只属于历史
  `0.6.0 → 0.7.0` 的 `ledger_absent` 恢复证据，不表示 0.7.1 支持从 0.6.0 直接升级。

### 发布治理

- 增加 Apache-2.0 `LICENSE`、`NOTICE`、唯一 DCO 签署流程以及 GitHub private advisory
  漏洞报告入口；这些公开治理材料与 SBOM 一并进入正常安装包。

## 0.7.0（待发布）

### 兼容与升级

- 插件支持 SandAdmin `6.x`，数据库仅支持 PostgreSQL。
- fresh install 使用根与插件镜像一致的 `001–038` 迁移集合；当前正式声明的历史升级入口为
  `0.6.0 → 0.7.0`，只执行 `033–038`。不得跨过未声明版本或手工改写迁移账本。
- 已发布的 `021_admin_permission_catalog.pgsql` 保持不可变；后续修复继续追加新迁移。
- 当前候选不声明公开接口、稳定错误码或组织/应用/环境隔离语义的不兼容变更。未来若需要
  不兼容变更，必须先发布版本、迁移和 API/SDK/页面同步说明。

### 新增

- `033_identity_group_role.pgsql`：身份、用户组与角色关系。
- `034_identity_group_role_permission_catalog.pgsql`：三项用户组角色管理权限目录，不自动授予既有角色。
- `035_schema_migration_ledger.pgsql`：带结构指纹前置校验的 SandIAM 迁移账本。
- `036_acceptance_fixture_support.pgsql`：发布验收支持；验收接口在正常运行配置中默认关闭。
- `037_initialization_draft.pgsql`：初始化草稿与修订记录。
- `038_auth_rate_limit_retention.pgsql`：为认证限流过期状态的有界清理增加 `(window_start, id)` 访问路径。
- 增加默认关闭的运维状态保留 worker：按 30–3650 天策略分批删除过期 `succeeded` 幂等记录，并按
  1–168 小时策略分批删除过期认证限流窗口；pending 幂等记录与审计日志不进入该清理范围。
- 增加 OIDC 后通道登出 dead 投递恢复：保留原失败证据，重新签发短时 logout token，并以确定性
  后继事件收敛重复和并发恢复；列表、响应和审计均不暴露 token 或密文。
- 管理 OpenAPI 契约提升为 `0.13.0-candidate`，为上述恢复操作公开精确分页参数、请求/响应 DTO、
  稳定错误码及 404/503 响应；运行端点与既有隔离语义保持兼容。

### 发布材料

- 增加中文安装升级、首次接入、管理员、应用用户、安全、备份恢复、排障及发布包校验说明。
- 增加 CycloneDX 1.6 SBOM、第三方许可告知、贡献说明和漏洞报告指南。
- 候选构建统一排除测试、内部任务材料、本机路径、秘密、缓存和非运行时构建目录；TypeScript
  SDK 的受控 ESM `dist` 是唯一明确例外。
- 增加可复现 ZIP、包外 Ed25519 证明及逐条目校验流程。正式签名仅可绑定干净、已提交、
  已获批许可证且通过全部发布门禁的 `release/unsigned` 候选。

### 尚未完成的发布条件

当前源码仍是未发布候选。正式安装/升级/卸载、七条真实业务链、四角色页面、标准协议对端、
非 AI 业务应用与机器服务、并发/备份恢复、同候选 24 小时稳定性、Casdoor 独立对照、最终许可
及签名必须全部形成当前证据后，才能移除“待发布”状态。

## 0.6.0（历史基线）

当前仓库只把 `0.6.0` 作为受支持升级来源和已发布迁移不可变基线。本文件不重建其原始发行说明；
需要审计历史行为时，应使用当时发布包、标签及其原始校验值，不能从 0.7.0 候选反推。

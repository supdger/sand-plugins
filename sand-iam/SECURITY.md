# Security policy

## 报告漏洞

请使用代码托管平台提供的私密漏洞报告或 Security Advisory 功能联系维护者。
如果当前镜像没有私密报告入口，请通过项目所有者公布的私下联系方式联系维护者，
不要创建公开 issue，也不要附加真实凭证、个人数据或生产数据库副本。

报告中请包含：

- 受影响的 SandIAM、SandAdmin 和 PostgreSQL 版本；
- 受影响的部署方式、协议、接口或页面；
- 最小复现步骤、预期结果和实际结果；
- 安全影响、所需权限和是否可跨组织或跨应用；
- 已脱敏的请求 ID、错误码和日志；
- 你认为安全的披露时间与联系方法。

维护者确认收到后，应先复现和界定影响，再协调修复、回归、版本和披露。修复发布前，
请不要公开利用细节。请勿在未经授权的系统上测试。

## 支持范围

正式发布时以发行说明列出的当前版本和仍在安全支持期的历史版本为准。
源码候选、开发快照和第三方修改版不自动获得生产支持，但仍欢迎私下报告可能影响正式版本的问题。

## 部署方责任

部署方必须使用 TLS、受控密钥存储、最小权限、审计保留、备份恢复演练和及时依赖更新。
验收专用接口在发布状态应保持关闭。凭证或签名密钥疑似泄露时，应立即轮换或撤销，
并核查撤销后的访问和审计记录。

# SandIAM 产品需求（平台控制面）

> 本需求定义开源 SandIAM 的通用能力，不绑定任何行业或接入应用。演示数据可使用明确标注的记录值，但功能名称、说明、引导、注释、占位、错误和通用接口示例必须行业中立。

## 1. 目标

SandIAM 是基于 SandAdmin 的 PostgreSQL 插件，为平台和接入应用提供通用的身份、组织、应用登记、服务授权、策略判定、数据范围和审计能力。它可单独安装；与 SandAI 或其他服务配合是可选服务接入场景，不是运行前提。

它解决两类问题：

1. 管理一个接入应用的客户主体、应用、环境、服务调用身份和服务授权；
2. 为接入应用提供独立的应用用户身份、认证、会话、角色、策略、数据范围和审计能力。

SandAdmin 后台账号只用于平台治理，不替代接入应用的最终用户账号。

## 2. 首期对象与关系

```text
organization（客户主体）
└── application（接入应用）
    └── environment（应用环境）
        └── workload_client（服务调用身份）
            └── service_grant（服务授权）
```

- `organization`：独立客户或业务主体，是数据隔离与授权范围边界。
- `application`：登记到平台、需要使用平台能力的产品或系统，不是最终用户。
- `environment`：同一应用的开发、测试、生产等隔离边界。
- `workload_client`：应用后端调用已登记服务的机器身份，不是人的登录账号。
- `service_grant`：某调用身份可调用的服务动作、服务受众及约束。

用户、业务对象、业务状态和业务规则始终归接入应用；SandIAM 只保存身份、授权事实和审计事实。

## 3. 身份与授权边界

SandIAM 参考 Casbin 的可配置策略模型和 Casdoor 的身份、组织、应用管理能力，但遵守以下边界：

- 应用身份、凭据、会话与授权关系按应用隔离；相同外部标识不能自动合并。
- 应用间共享登录只能通过明确的联合身份配置实现。
- 用户类型、角色、资源、动作、策略与数据范围可配置；具体业务含义不硬编码到插件。
- 策略允许、拒绝和范围判断必须由后端给出可信结论，前端不能自行推断。
- 调用凭证、密钥、令牌和恢复材料只写不读；明文只在允许的一次性场景出现。

## 4. 必须提供的能力

1. 客户主体、接入应用、应用环境和服务调用身份的创建、查看、修改、停用与审计。
2. 服务目录、服务动作、服务授权、凭证签发/轮换/撤销和调用审计。
3. 身份源、应用用户、用户组、邀请、导入导出、同步、用户类型、角色、资源、策略和数据范围。
4. 注册、登录、会话、MFA、通行密钥、密码恢复、锁定与撤销。
5. OAuth/OIDC、联合身份、SCIM、CAS、Kerberos/RADIUS 等协议能力按明确的启用条件和验收边界提供。
6. 应用业务动作、接口目录、路由绑定、路由清单预检与确认、策略模拟和可追溯审计。
7. 管理委派、事件通知、投递重试、安全告警、审计保留和初始化预检。

## 5. 管理委派与产品体验

- 平台管理员管理全局目录、服务能力和客户主体委派。
- 客户主体管理员只管理被授予客户主体内的接入应用。
- 应用管理员只管理被委派接入应用的用户、策略、调用和通知配置。
- 应用用户只在独立运行面使用应用账户、会话与安全能力，不使用 SandAdmin 后台会话。

总览、首次使用向导、状态文案、可点击入口和七条业务闭环必须满足[产品体验与闭环交付契约](../development/sand-iam-product-experience-contract.md)。未完成能力不展示为可点击的半成品。

## 6. 与服务插件的配置边界

| 配置事项 | 权威方 | 接入应用管理员可做什么 | 不可做什么 |
| --- | --- | --- | --- |
| 平台后台账号、插件菜单与全局治理 | SandAdmin | 使用被授予的管理入口 | 把后台账号当成应用用户账号 |
| 应用用户、用户类型、登录与业务授权 | SandIAM 提供能力；接入应用负责配置 | 在授权范围内配置通用身份与授权事实 | 将具体业务规则硬编码进 SandIAM |
| 组织、应用、环境、调用身份、凭证与服务授权 | SandIAM | 在被委派范围内查看和配置 | 触及其他客户主体或扩大自身授权 |
| 服务能力的供应商配置、路由与执行 | 对应服务插件或服务提供方 | 从已发布、已授权的目录中选择能力 | 修改未获授权的服务能力或接管业务数据规则 |
| 接入应用的业务实体、业务状态和业务规则 | 接入应用 | 保存实体并调用 SandIAM 做授权判断与审计 | 迁入 SandIAM 的通用表 |

## 7. 验收要求

- 管理员能够完成客户主体 → 接入应用 → 应用环境的真实创建、修改、停用或恢复。
- 用户、授权、登录、系统调用、接口治理、管理委派和事件通知必须实际验证允许与拒绝、审计、撤销或恢复与夹具清理。
- 宿主、浏览器、外部协议、业务闭环和可部署性必须分别报告；构建通过不能替代任何运行证据。
- 不新建数据库，除非用户在当次任务明确授权。

## 8. 服务接入验收

任何服务接入都以真实业务 API 的允许、拒绝和双侧审计为验收边界：服务插件只消费 SandIAM 的身份与授权上下文，接入应用仍负责最终业务状态判断。静态 SDK 测试、接口响应或管理台配置保存不能替代该闭环。

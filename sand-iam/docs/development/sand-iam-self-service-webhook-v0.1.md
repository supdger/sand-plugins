# SandIAM 委派、自助服务、Webhook 与审计契约（IAM-T06，v0.1 候选）

> 状态（2026-08-22）：后端候选已落源码，`009–010` 已进入根与插件生命周期，委派/Webhook 隔离 PostgreSQL 集成已有执行记录。真实宿主 HTTP、并发 worker、真实 HTTPS 接收端和三角色浏览器流程尚未验收。本文不能作为已上线承诺。

## 1. 三种人从哪里进入

| 使用者 | 使用身份 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| 平台管理员 | SandAdmin 超级管理员 | 管理全部客户主体、接入应用、应用委派、平台目录和全局安全配置 | 不能把后台账号当成接入应用的最终用户 |
| 客户主体管理员 | SandAdmin 后台账号 + 客户主体委派 | 管理本客户主体下的应用，并给具体后台账号分配应用管理范围 | 不能读取其他客户主体，也不能创建平台全局服务目录 |
| 应用管理员 | SandAdmin 后台账号 + 接入应用委派 | 只管理获授应用的身份、身份源挂载、接口、Webhook 和应用配置 | 不能给自己增加应用范围，不能修改共享身份源密钥或其他应用 |
| 应用用户 | SandIAM 应用会话 | 查看和修改自己的资料、密码、会话、MFA、通行密钥和外部账号连接 | 不能进入 SandAdmin，也不能管理其他用户 |

客户主体委派自动覆盖该主体下当前启用的应用。应用委派只覆盖一项接入应用；委派停用后，下次管理请求立即重新计算范围，不把旧范围写进长时间缓存。

## 2. 应用用户自助入口

所有自助接口都使用应用自己的 SandIAM access token：

| 接口 | 用途 | 重要行为 |
| --- | --- | --- |
| `GET /api/sand-iam/v1/me/profile` | 查看自己的应用身份资料 | 只返回当前应用身份，不返回密码哈希或外部身份原始 subject |
| `PATCH /api/sand-iam/v1/me/profile` | 修改显示名称 | 写入审计，不允许改变所属应用或稳定身份 ID |
| `GET /api/sand-iam/v1/me/connections` | 查看已连接的外部账号 | 只显示掩码提示；身份源已停用或已从本应用卸载时标明不可用 |
| `GET /api/sand-iam/v1/me/security` | 查看安全概况 | 汇总本地密码、有效会话、TOTP、通行密钥和外部连接数量 |
| `POST /api/sand-iam/v1/auth/password/change` | 修改当前密码 | 校验当前密码与新密码策略；成功后撤销该身份的全部会话和刷新令牌，用户需重新登录 |

原有会话、MFA 和通行密钥接口继续承担具体操作；安全概况只是入口汇总，不复制认证器密钥。

## 3. Webhook 配置与接收

Webhook 归接入应用。创建和轮换时签名密钥只返回一次，数据库只保存带密钥版本的加密值。接收地址必须是 HTTPS；禁止 URL 用户名/密码、片段、内网或保留地址、代理和跳转，并固定请求发出前解析得到的公网地址，降低 SSRF 与 DNS 重绑定风险。

每次请求包含：

```text
X-SandIAM-Event-Id: evt_...
X-SandIAM-Event-Type: identity.updated
X-SandIAM-Timestamp: 1787280000
X-SandIAM-Secret-Version: 2
X-SandIAM-Signature: v1=<hex hmac-sha256>
```

接收方必须按以下顺序处理：

1. 拒绝与当前时间相差超过 300 秒的时间戳；
2. 按 `X-SandIAM-Secret-Version` 选择仍处于接收过渡期的密钥；
3. 使用收到的**原始请求体**计算 `HMAC-SHA256(timestamp + "." + raw_body)`，以常量时间比较签名；
4. 以 `X-SandIAM-Event-Id` 去重，已经成功处理的事件直接返回 2xx；
5. 业务处理与事件 ID 落库应位于同一事务。

投递只把 2xx 视为成功；失败按 60 秒、5 分钟、30 分钟、2 小时、12 小时退避，达到应用设置的最大次数后进入失败终态。后台可以查看投递摘要和错误码并手工重试，但列表不展示完整 payload，响应正文也只保存 SHA-256 摘要。

事件 payload 禁止密码、access/refresh token、Authorization、客户端密钥、加密配置、SAML Response 和凭证明文；单个 payload 上限 64 KiB、最大嵌套 8 层。

当前候选实现已提供显式 `WebhookService::enqueue()` 采集端口和投递 worker，`010` 生命周期对象已经进入安装/升级链路。身份注册、资料修改、停用等核心生产者仍须逐项以事务 outbox 接线并留下事件目录、事务一致性和失败重试证据；不能因为投递表已经安装就宣称所有事件会自动发送。

候选阶段 worker 默认关闭。部署方只有在目标数据库确认包含 `010`、完成空宿主安装/升级、worker 并发抢占和进程重启验收后，才可设置 `SAND_IAM_WEBHOOK_WORKER_ENABLED=1`。当前宿主数据库处于待恢复状态，不得用隔离生命周期记录替代宿主启用验收。

## 4. 审计查询与导出

审计列表、详情和导出执行同一管理范围判断：应用管理员只看到获授应用，客户主体管理员看到获授主体，超级管理员才有全局范围。

导出必须填写起止时间，范围不超过 31 天，单次最多 10,000 条；CSV 对以 `= + - @` 开头的文本加前缀，避免电子表格公式注入。响应使用 `no-store`，导出权限为 `sand_iam:audit:export`，拥有列表权限不代表自动拥有导出权限。

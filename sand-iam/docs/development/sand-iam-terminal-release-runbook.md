# SandIAM 完整开源成品交付计划

## 1. 目标、主线与完成标准

在 `/Users/code/project/sand_plugins` 交付普通开发者能够按公开中文文档安装、配置、接入业务并可靠使用的 SandIAM 插件，包含可发布源码、完整安装包、文档和验收证据。

**执行主线是持续完成用户登录与授权、真实业务应用接入、机器调用服务，以及全部既定产品能力。** 每批形成一个用户可观察的行为变化或补齐其真实验收证据。环境、宿主、工具、签名和报告只在解除当前业务动作的直接必要依赖时进入当前执行范围；其余作为对应验收或发布工作安排。

完整功能与最终发布标准不降低。验收条件决定何时可以声明通过，不自动成为所有需求开发的前置条件。实现已满足时进入真实验收，不重复实现、增加新需求或制造离线准备维持进度。

只有既定 48 项 FLOW 原子全部通过、10 项发布门槛全部通过、无发布阻塞缺陷且独立终验通过，才能判定“SandIAM 可发布”。单项 PostgreSQL 回归、源码审查、构建、包生成或截图只证明各自范围。

终点不含公开推送、正式 Release、生产部署或线上验证；这些状态须另行授权、执行和报告。

## 2. 权威入口与首次基线

- 权威插件源码为 `sand-iam/`；演示与真实宿主验收使用本仓 `sandadmin-demo-host`，服务端为其 `server/`。通用 SandAdmin 仓库不作插件演示目标。
- 本文规定交付与调度；[任务看板](sand-iam-task-board.md)保存当前动作、依赖、写者和进展；[验收账本](sand-iam-terminal-acceptance-ledger.md)保存验收定义和证据；`.codex/autopilot/tasks.md`沿用已有 OSS 编号作粗粒度队列。不再建立另一套状态表或队列。
- 首次只读核对四件事：权威源码与当前写者、已有能力及可复用证据、剩余需求与已知阻塞、首个可执行业务切片及授权范围。达到这些条件即开始实施，不先全量重审历史材料。
- 当前已有持续 Goal 时沿用原 Goal，不另建、不清空进度、不恢复旧 SandIAM 任务或旧 Codex/Cursor Autopilot、DETECT。仅在首次执行且确无当前 Goal 时，完成基线后按本计划创建持续 Goal。
- 版本、候选、分子与实时运行状态只引用现有证据。旧勾选不自动继承；已证明未受变更影响的有效证据按账本复用，不因换候选编号全量重测。
- 遇到旧文档与当前要求冲突，在原入口纠正；历史记录保留其时点和证据价值，不再充当当前唯一下一步。

## 3. 业务优先级与完整能力

按下列顺序选择**尚未完成且当前可执行**的用户结果。必要依赖按证据补齐；前一行受阻时选择其他无依赖项，不把表格变成全局串行队列。C/F/L 沿用现有验收 ID，不新增分母。

| 优先结果 | 用户应实际获得什么 | 既有链路与边界 |
| --- | --- | --- |
| 接入所需基础 | 客户主体、应用、环境、管理员委派与隔离可供当前接入使用 | 按 C01/C06 补当前旅程必要部分，不先建设通用宿主平台 |
| 用户登录与授权 | 应用用户能注册或接受邀请、登录、取得业务权限、访问允许资源；无权、跨应用及撤权访问被拒绝并留审计 | C02/C03、L02/L04；应用用户不复用宿主后台账号 |
| 真实非 AI 业务应用 | 普通开发者用 SDK/中间件接入真实业务 API，完成登录、资源 allow/deny/scope、隔离、审计和清理 | C02/C05、L04；业务实体和状态归应用，不搬入 IAM |
| 真实机器服务 | 机器身份取得授权和凭证，成功调用产生真实业务副作用；错误 audience/action、无权与撤销后拒绝，双侧审计可关联 | C04/C05、L03；使用受控非 AI 服务，不等待 SandAI |
| 全部剩余 IAM 能力 | 协议、身份源、目录、会话安全、自助、治理、委派和事件能力按既定范围可用 | C01–C07 全覆盖，外部条件只限制相关路径 |

必须完成且不得以“后续优化”删除的能力：

- 客户主体、应用、环境、管理委派、身份与应用隔离。
- 身份、用户组、角色、资源、策略、版本与数据范围。
- 注册、登录、恢复、会话、MFA、Passkey、自助门户与撤销。
- 机器身份、凭证轮换、服务授权、调用限制和撤销重验。
- OAuth/OIDC、联合身份、目录同步、SCIM、CAS、Kerberos/RADIUS，以及既定契约中的其他身份协议能力。
- 接口登记、路由绑定、SDK、中间件、初始化配置和开发者接入。
- Webhook、重试、审计、告警与安全运营。

保留现有公开接口、错误码和身份隔离语义。不兼容变化必须先确定版本、迁移与消费者影响，再同步 API、SDK、页面及文档。

## 4. 每批如何推进

1. **选择结果。** 在原任务板记录需求/验收 ID、下一项用户可观察行为、现有实现、最小改动或验证、直接依赖、当前写者。挑选原需求，不挑选“容易产生输出的工作”。
2. **实施与聚焦回归。** 复现缺口，修改权威源码，运行适用检查；已有实现直接验证。新增测试必须证明生产行为或公开契约，不能仅检验辅助工具。
3. **进入真实验收。** 条件具备时在受控 demo、真实数据库、浏览器、业务应用或标准对端验证适用行为、异常、拒绝、撤销、审计和清理。缺条件就保留该项未通过，不改用模拟结果冒充。
4. **隔离后交独立验收。** 固定候选、改动及证据范围，由独立上下文复核。主控继续不依赖此结果的下一需求；共享数据库、服务和文件操作由主控协调，禁止并发争用。
5. **记录可用结果并继续。** 指出实际入口、可用行为、验证层级和缺口，只更新有证据支持的状态。发现缺陷修复受影响范围，不重新审查未受影响的全部材料。

“每批一条业务链”指同一实现切片保持业务完整，不表示必须等整条链、全部外部对端和发布条件通过后才能实现下一需求。完整链仍须按创建、真实生效、允许/拒绝、撤销/恢复、审计和清理完成最终验收。

## 5. 支线、阻塞与停止规则

辅助工作开始前必须说明：**具体阻止的业务动作、必要性证据、最小范围、结束条件**。只为该动作修复当前必需部分；解除依赖即返回业务。无直接依赖的同步工具扩建、锁文件体系、报告美化、治理脚本和验证器扩展不进入当前执行。

一次动作被拒绝或环境缺失后：

1. 保留该动作的原始拒绝或失效证据，不重复被拒操作，不换工具、命令或会话规避限制。
2. 按原需求检查其他主要路径，分清可执行、已检查但受具体条件阻塞、未核查。找到一项安全且已授权的原业务动作立即执行，停止扩大搜索。
3. 未核查不等于受阻。若准备结束执行，仅补决定下一步所需的最小取证；不能因为两个用例受阻就声称整个产品无法推进，也不为证明“全局无事可做”开展全仓审计。
4. 曾误判或被用户纠正的全局阻塞，在再次提出或依据发生实质变化时，交独立上下文作一次有界复核，重点查遗漏动作和无依据依赖；未变依据复用。复核缺失如实标注，不伪造完成，也不违反 Goal 状态时序。
5. 只有全部剩余动作被具体外部条件限制时，才按 Goal 工具规定处理阻塞。未完成范围、证据和恢复所需条件保留；恢复后接续下一动作，不清空基线或重做已通过项。

每 60 分钟有效执行、验收返工或同一节点连续两轮修复仍失败时检查净进展。只认可观察行为及其验证、真实验收通过、必要依赖解除或有证据排除竞争解释；计划、日志、测试数量、候选数量和辅助产物不算业务进展。

无净进展时停止原假设下扩建，作最小诊断或选择其他原需求。同一版本、同一错误且无新证据不得反复唤醒；宿主单变量诊断最多三轮，第三轮仍无可区分结论就保留该局部阻塞。交接、压缩、换 Agent 或候选不重置失败计数。

## 6. 宿主、授权与协作边界

- 不创建数据库，不允许安装器、迁移、测试或运行时隐式创建。需要空库时，等待本次明确授权或外部管理员提供预创建受控环境；相关条件不自动阻塞无依赖业务开发。
- 数据库写入及清理、迁移、服务启停、宿主同步、密钥操作、外部发送、提交、推送和部署各自遵守本任务明确授权。本文只规定工作，不授予这些副作用权限。
- 所需授权先准备到具体、可审阅：目标环境、动作、范围、数据影响、清理/回退方式及验收结果。已有有效授权保存原文位置与范围，同一范围不重复询问；旧任务授权不自动外推。
- 插件源码 → 经授权受控同步 demo → SandPackage 正式安装/升级 → 对应验收。禁止直接编辑 demo、从 demo 反向同步源码或由插件任务修改通用 SandAdmin。
- 宿主问题按插件复现 → 证明通用缺陷 → 现有 HOST 记录交接 → SandAdmin 发布明确修复 → 插件侧受控同步 → 复测处理。不扩建宿主工程；必要安装安全前提保留，其他业务工作继续。
- 前端按当前仓库已确认主责执行。当前 2026-09-13 覆盖为 Codex 接管，Astra 设计与实现、不同上下文 Astra 做真实平台验收；旧计划中的 Cursor 分工不自动恢复，用户后续明确改派则遵从新指令。
- 主控持续负责需求选择、实现/验收调度、授权、最终证据及完成判定。子 Agent 只承担有明确输入、范围、产出和结束条件的工作，不自行续建支线；复杂诊断及关键判断按现有编排规则交 Astra。

## 7. 发布准备如何进入主线

来源、许可和安全缺陷可能是某个具体安装或运行动作的必要前提，应及时处理。其他发布工作在不占用当前业务关键路径的情况下准备，最终统一收口，不要求每轮重新检查全部材料。

- 保留或补齐可商用、允许闭源集成的宽松开源许可及第三方再分发条件。已有确认决定沿用；真正未确认的许可证在依赖核查后提交明确方案，不反复重开已完成决策。
- 文档随已完成行为更新：安装升级、首次接入、管理员、应用用户、安全配置、备份恢复、排障、贡献和漏洞报告指南，均提供中文说明。
- 正式候选绑定干净 SandAdmin revision、SandIAM commit/tree、依赖版本、构建输入和包摘要；验证可复现构建、来源追溯及包外签名。
- 包内包含全部运行载荷、依赖、迁移、SDK 和公开文档；排除内部任务材料、秘密、本机路径、测试账号和行业专属内容；验收专用接口在发布状态默认关闭。
- 使用 SandPackage 正式完成全新安装、支持的历史升级、重复升级、失败恢复和卸载；已发布迁移保持不可变。裸 SQL/Service 回归不能替代正式插件生命周期。
- 当前候选具备适用条件后尽早安排标准对端、独立体验和长稳所需资源，避免最终才发现缺失；环境准备仍遵守范围与授权，不自动成为无关实现的前置。

## 9. 汇报、恢复与本次执行纠偏验收

每个里程碑简洁报告：**现在能用什么、实际验收多少、剩余什么、下一动作、是否可发布**。分开说明需求、模块实现、正式 FLOW、本地业务闭环、可上线部署、已提交、已部署和线上验证；产品状态与工具/文档完成状态不能混算。

交接保留当前用户成果、稳定验收 ID、候选与可复用证据、未完成/受阻/未核查项、下一动作、失败计数、写者和授权原文。旧任务、旧自动化不因新计划而重启；已有原任务实际重读后执行本计划。

本次 Agent 与计划优化按有限结果验收：新规则与计划已应用且入口一致；原任务实际重读；下一步选择能区分真实依赖与验收/发布条件；遇局部阻塞能检查并执行其他获授权业务动作，或有证据说明具体外部阻塞；不再将未知当成全局阻塞。规则安装和消息送达不单独算作执行纠正完成。

这些是可执行工作流与独立复核要求，不是模型权重修改，也不声称工具层已经强制保证所有未来任务永不偏航。安全审批故障另按受支持通道处理，不在本次优化中放宽、关闭或绕过。


## 附录：对应验收面的既有技术操作要求

本附录按验收面组织，章节排列不代表整个产品的执行顺序。只执行当前动作适用且已授权的条款；裸 SQL 生命周期和 Service 回归属于对应技术证据，不能替代第 8 节要求的 SandPackage 正式生命周期与完整用户旅程。当前候选、宿主状态、已执行授权和通过计数以任务板、验收账本及对应 HOST 记录为准，不能由历史执行说明推断。

### 1. 执行前授权与隔离

- 本计划不创建或删除数据库。数据库验收只可在用户明确指定的既有受控数据库中进行；若某项
  必须依赖全新空库，则等待用户或外部管理员提供预创建环境，不得由安装器、迁移、测试工具
  或运行时隐式创建；
- 执行前核对本任务对 SandIAM 根/插件生命周期 SQL 修改的明确授权，不因本附录而扩权；
- 宿主同步、进程重启、`.env` 密钥写入、业务仓库修改、真实外部身份源连接和部署分别授权；
- 不使用生产库、生产密钥、真实用户隐私或真实业务数据做验收。

| lifecycle | 根与插件 install/update/uninstall 实际展开结果一致；包含表、约束、索引、菜单和权限；卸载逆序清理 |
| 元数据 | 根/插件 `info.ini` 版本一致，README 状态不超过证据 |
| 包内容 | PHP 依赖、管理端载荷、运行面静态资源、SDK、文档和迁移均按[当前包契约](sand-iam-package-integrity.md)进入发布包，不含 node_modules、测试密钥和本机路径。0.7.2 正常包排除根/插件的历史 `recovery/failed-upgrade.v2.json`，不得为满足历史条款重新加入或改绑当前版本。仅对实际声明该描述器、绑定对应历史版本的受控恢复包，核验根/插件字节一致、递归 canonical、内联受限 profile、descriptor-excluded 载荷摘要及根 `update.sql` 摘要；历史恢复要求仍须在其适用场景验收 |
| PostgreSQL | 无 `AUTO_INCREMENT`、`UNSIGNED`、`ENGINE=`、反引号或新增 `sa_*` 业务表 |

### 3. 既有受控 PostgreSQL 环境中的生命周期

取得本任务精确授权后按以下顺序运行。任何一步失败立即保留日志、停止后续写入并清理本次
插件夹具；不得创建、删除或重建数据库：

1. 空库执行根 `install.sql`；记录 SandIAM 表/约束/索引/菜单/权限实际数量；
2. 执行两次根 `update.sql`，证明幂等；
3. 运行 T01–T06 所有真实 ORM 集成测试；
4. 从 `0.1`、`0.2`、`003`、`005`、`007` 边界分别升级到当前，核对回填、唯一约束与跨应用拒绝；
5. Webhook 两 worker 并发 `SKIP LOCKED`，同一投递只能被一个 worker 领取；
6. 执行根 `uninstall.sql` 两次，SandIAM 表、菜单和权限残留均为 0；
7. 清理本次 SandIAM 夹具并核对宿主及其他插件未受损；数据库本身保持不变。

不能用事务回滚替代 fresh install/update/uninstall；业务测试可以在事务中回滚，但生命周期必须真实提交。

### 4. 真实宿主 HTTP

受控同步到 `/Users/code/project/sand_plugins/sandadmin-demo-host` 后完整重启演示宿主（服务端为其 `server/` 子目录），再验证。`/Users/code/project/sandadmin` 保持纯净通用宿主，不用于插件演示：

- 注册 → 验证 → 登录 → 刷新 → 会话 → 改密全撤销 → 新密码登录 → 退出；
- TOTP、恢复码、Passkey 真实浏览器仪式；
- OAuth/OIDC discovery、JWKS、Code+PKCE、userinfo、refresh rotation、revoke、logout；
- 外部 OIDC/OAuth、SAML、LDAP、SCIM 使用标准客户端/测试服务，不只调用内部 PHP 方法；
- API 决策和 Webman 中间件允许/拒绝、audience/scope、路由冲突和数据范围；
- Webhook 真实 HTTPS 接收端验证原始 body HMAC、时间窗、事件 ID 去重、失败重试、密钥轮换；
- 审计导出下载、31 天/10,000 条限制、CSV 注入防护和 no-store。

每条请求保存调用方和 SandIAM 共同的 `X-Request-Id`。证据中不出现密码、验证码、完整 token、TOTP seed、恢复码、client secret、Webhook secret 或身份源密钥。

### 5. 四角色浏览器

分别使用平台管理员、客户主体管理员、应用管理员、独立应用用户会话，在 `1440×900` 与 `1280×720` 验收：

- 平台管理员：创建客户主体/应用、委派、全局目录、审计；
- 客户主体管理员：只看到获授客户主体，管理其应用/环境并委派应用管理员；越主体访问被拒绝；
- 应用管理员：只看到获授应用，配置认证、身份源、用户/角色/策略、OAuth 客户端、API、Webhook；撤权后刷新即失效；
- 独立应用用户：不进入 SandAdmin，完成注册或邀请激活、登录、恢复、资料、密码、会话、MFA、Passkey、外部账号连接；
- 默认列表只显示业务名称和可操作状态；ID/代码为辅助，JSON 不平铺；
- 加载、空、失败、无权、停用、冲突和功能未配置状态可区分并可恢复。

测试夹具要记录创建清单和清理清单；浏览器截图不能代替数据库/审计清理证明。

### 6. 两个真实业务接入

#### 非 AI 机器调用服务

- 受控机器服务幂等登记 service/action，不依赖 SandAI；
- 获授 workload client 调用一个真实、有可观察业务副作用的服务动作成功；未授权、错误
  audience/action、过期、重放和撤销凭证均失败；
- SandIAM 与机器服务双侧审计使用同一请求标识关联，最后撤销授权并清理业务副作用。

#### 非 AI 业务应用

优先使用一个受控接入应用的真实业务详情或列表接口：

- PHP/TypeScript SDK 完成登录和接口代码授权；
- 业务后端对 list/read/write/export 使用真实业务属性执行 scope；
- 同手机号在另一应用独立注册不串账号、不共享登录；
- 前端隐藏按钮只作体验，直接请求业务 API 仍由后端拒绝。

### 7. 安全、并发与恢复

- 密码、验证码、token、恢复码、OAuth/Webhook/身份源秘密的库/消息/日志/审计/导出泄露扫描为 0；
- 登录、验证码、MFA、密码重置、OAuth、SCIM、Webhook 管理动作的限流与重放拒绝；
- 并发刷新、授权码消费、SCIM upsert、身份绑定、应用委派撤权和 Webhook 抢占；
- OAuth、MFA、Webhook 和 federation keyring 轮换期间旧密文/旧签名可按窗口验证，窗口结束后拒绝；
- PostgreSQL 备份恢复到新临时库后，授权、会话撤销、审计链和验签仍一致；
- 关闭 SandIAM 或移除 required plugin 时，机器服务与业务接口 fail closed，不降级放行。

# SandIAM 应用账号生命周期、用户组与同步契约（v0.1 草案）

> IAM-T10 契约。账号生命周期/用户组、邀请、访客升级、CSV 和通用 Syncer 已有后端候选；`012–015` 与 Syncer 组织/应用约束 `026` 已进入根生命周期并通过 SandPackage 安装。账号生命周期/用户组/访客、邀请和 Syncer 已通过 PostgreSQL 集成，真实 HTTP、调度、具体目录驱动和页面验收尚未完成。

## 1. 不再造一套用户

- `sand_iam_identity` 仍是某个接入应用里的稳定应用用户 ID；邀请、访客升级、停用、删除和恢复都不能换 ID；
- `sand_iam_identity_auth` 仍保存该应用账号的本地认证材料；
- `sand_iam_scim_*` 继续表示某个外部身份源投影到应用的目录资源，不能直接当成本地用户组；
- 新增的“应用用户组”只在单个接入应用内组织用户，可被角色/策略引用，但不跨应用拼接账号；
- 导入导出是应用账号管理工具，不是跨产品数据汇总工具。

## 2. 管理员和用户看到的状态

接受邀请时，身份激活、初始入组、邀请消费、同目标其他有效邀请的撤销与接受成功审计在同一事务提交。成功审计失败会回滚本次接受，邀请未过期且仍有效时可重试。已经成功提交的邀请不能再次接受；此回滚保证不提供成功响应丢失后的响应恢复，也不会自动登录。

| 机器状态 | 中文 | 能否登录 | 管理员能做什么 |
| --- | --- | --- | --- |
| `pending` | 等待接受邀请 | 否 | 重发、撤销 |
| `active` | 正常 | 是 | 停用、加入用户组 |
| `disabled` | 已停用 | 否 | 恢复启用、删除 |
| `guest` | 访客 | 仅允许应用明确授予的访客流程 | 发起升级、停用、删除 |
| `deleted` | 已删除 | 否 | 保留期内恢复；到期后清除认证与关系 |

数据库 `status=1/2` 继续作为统一启停兼容字段；新增 `lifecycle_state` 表达业务状态。所有登录、刷新、联合登录、SCIM、授权和管理查询必须同时检查两者，不能只在页面隐藏。

停用立即撤销会话和刷新令牌，但保留 MFA、外部绑定、角色和用户组关系，重新启用后无需重建配置；旧会话永不恢复。删除采用两段式：先进入 `deleted` 并进一步撤销 MFA、通行密钥、外部绑定和活动授权关系；保留期内可恢复为删除前状态，但不恢复旧会话、令牌或已移除的授权关系；保留期到期后的物理清理由独立受控任务执行，必须有计数、审计和不可恢复确认。

## 3. 邀请与访客升级

管理员输入接收邮箱或手机号、有效期和初始用户组。SandIAM：

1. 校验应用、注册方式、管理员范围和同应用冲突；
2. 生成只显示一次的随机邀请 token，数据库只保存 HMAC；
3. 目标地址使用独立版本化密钥加密，并保存规范化指纹用于同应用去重；
4. 通过该应用挂载的邮件/短信服务投递；投递失败保持可重试状态，不伪造成功；
5. 用户接受邀请时一次性消费 token，设置用户名、密码和显示名称，创建或升级原访客 Identity；
6. 成功后撤销同目标未使用邀请，并写邀请、账号和用户组审计。

同一邮箱或手机号可在不同应用分别收到邀请。同应用重复有效邀请返回冲突；撤销、过期和已消费 token 均不能重放。邀请列表只显示脱敏目标，例如 `zh***@example.com` 或 `+86****1234`。

访客由业务产品使用受控服务身份创建，并必须提供稳定 `external_guest_id` 做应用内幂等。升级时原 `identity.id`、业务引用、用户组与审计链保持不变；不能新建正式账号后把业务数据迁过去。

业务服务先用 workload credential 申请 audience=`sand-iam`、action=`identity.guest.upsert` 的 5 分钟运行上下文，再调用 `POST /api/sand-iam/v1/guests/upsert`。应用 ID 只取上下文；请求中的 `external_guest_id` 原值不落库，使用独立 pepper 和应用 ID 生成 HMAC。管理员向访客发送升级邀请时绑定该访客，接受后原地补本地认证材料并切换为正常状态。

## 4. 应用用户组

用户组字段只让人看到：用户组名称、所属应用、上级用户组、成员数量、状态。系统代码在详情和编辑表单作为辅助字段，创建后不改；数据库 ID、父级 ID、成员 ID 和原始 JSON 不进默认列表。

约束：

- 用户组和成员必须属于同一应用；
- 父子关系最多 8 层，禁止把自己或后代设为父级；
- 删除有子组或有效成员的组必须先迁移/移除关系；
- 成员加入、移除和批量替换均使用事务、幂等键和审计；
- 外部 SCIM 组可显式映射到本地应用用户组，但来源组删除只停用映射，不擅自删除本地组。

## 5. 批量导入导出

导入分两步：上传并校验 → 展示逐行预检报告 → 用户确认后执行。第一版只接受 UTF-8 CSV，固定列名：用户名、显示名称、邮箱、手机号、账号状态、用户组代码。禁止公式、宏和任意动态列。

- 每个任务绑定应用，最多 10,000 行；
- 每行有来源行号、幂等键、结果和可读错误；一行失败不伪装整批成功；
- 默认只新增，显式选择后才更新；不支持通过缺行推断删除；
- 密码不允许导入；新用户采用邀请激活；
- 导出默认不含邮箱/手机号完整值，导出敏感字段需要单独权限、用途和审计；
- CSV 单元格以 `= + - @` 开头时加前缀，防止表格公式注入。

## 6. 通用 Syncer

Syncer 与登录身份源分离：身份源回答“如何认证/外部 subject 是谁”，Syncer 回答“从哪里按游标读取哪些账号和组”。一个同步连接必须归属客户主体并显式挂载到应用。

统一驱动契约按页返回：来源对象类型、稳定来源 ID、版本/更新时间、规范化属性、删除标记、下一游标。驱动只负责连接外部系统，不直接写 SandIAM 表；核心服务在事务中执行匹配、冲突策略、写入、停用传播和审计。

第一版核心驱动使用 `pullPage(config, cursor, 500)`、`pushBatch(config, events)` 和 `test(config)` 三个稳定方法。连接配置、游标、来源快照和出站事件负载均使用独立版本化密钥加密；来源 ID 只保存带连接域隔离的 HMAC。管理 API 只返回“已配置/已有游标”，不回显密文、明文配置、来源 ID、原始快照或驱动响应。 配置保存会锁定当前连接，按最新版本递增，并与成功审计一起提交；失败时密文、字段权威设置和版本一并回滚。连接归属已变化时拒绝陈旧页面保存，返回范围变化错误，刷新后重试。

固定模式：

- `inbound`：外部系统 → SandIAM；
- `outbound`：SandIAM → 外部系统；
- `bidirectional`：必须配置每字段权威方和冲突处理，否则禁止启用。

显示名称和用户组可分别声明 `source` 或 `local` 为权威方。来源用户组代码必须通过连接私密配置里的显式映射指向本应用已有用户组；任何未映射代码或不存在的目标组都会停止该页，不允许静默创建组或跨应用挂成员。`manual` 将本地和来源同时变化标为冲突，`reject` 使本次运行失败，`source_wins` 与 `local_wins` 只处理已明确声明的来源字段。

每页身份、用户组关系、来源快照、游标和运行计数在同一事务提交；保存失败时整页回滚，已持有的连接和运行对象重新加载，内存计数不提前增加。之前成功的页保留，重试从最后提交的游标继续。外部目录读取在该事务之外。同一连接同一应用只允许一个运行中任务。错误按可重试/配置错误/数据冲突分类，保留失败位置。来源缺失不能立刻删除账号：先标记 `source_missing`，超过保护窗口并通过停用阈值后才停用。若单次停用比例超过配置阈值，自动中止并等待人工确认。

管理端选中连接后，拥有 `sand_iam:sync_connector:update` 权限的管理员可点击“编辑保护设置”，修改连接名称、缺失保护时长（1–720 小时）、停用比例阈值（1–100%）和上述四种冲突策略。保存只更新设置，不执行同步，也不读取或重写连接密钥。保存失败保留草稿供修正重试；切换应用、连接或刷新到其他记录时取消旧草稿，避免将设置保存到错误连接。

当前候选支持管理端显式触发和默认关闭的目录同步 worker；应用用户注册、邀请激活、访客创建/升级、资料/用户组变更、停用、删除和恢复可在原业务事务内同时写入 Webhook 与出站 Sync outbox。该事件生产能力由 `SAND_IAM_IDENTITY_EVENT_OUTBOX_ENABLED` 显式开启，默认关闭，避免生命周期表尚未安装时破坏既有认证流程；来源同步触发的本地停用会抑制反向 Sync 回声。出站拒绝或驱动异常按 `SAND_IAM_SYNC_OUTBOX_MAX_ATTEMPTS` 有界累计，达到上限进入 `failed`；同应用管理员修复对端后，可用 `outbox`/`outbox-retry` 查看脱敏状态并精确重新排队，重试与 running 同步互斥且留审计。具体数据库/企业目录驱动虽已有候选实现，但没有真实对端证据时不能把“通用核心已实现”写成“已连接真实目录”。

内置 `postgresql` 驱动提供第一个可配置数据库来源，但只允许入站。连接 DSN 必须使用 `pgsql:` 且包含 `sslmode=verify-full`；数据库事务固定为 `BEGIN READ ONLY`，查询必须是单条 `SELECT/WITH`，包含 `:cursor` 与 `:limit`，并禁止写入关键词、注释和分号。查询列统一别名如下：

```sql
SELECT id::text AS source_id,
       updated_at::text AS source_version,
       display_name,
       false AS deleted,
       group_codes
FROM external_users
WHERE id::text > :cursor
ORDER BY id::text
LIMIT :limit
```

`source_id` 必须稳定且与排序一致，`source_version` 每次来源事实变化时必须变化；`group_codes` 可为 JSON 字符串数组或 `|` 分隔代码，并且仍需通过连接配置的 `group_map` 显式映射成本应用用户组。当前测试证明配置拒绝、行规范化、方向能力，以及假驱动下的全量/增量、双向 outbox、冲突、缺失保护、停用阈值和跨组织拒绝；尚未连接真实外部数据库或企业目录。

## 7. 验收底线

必须证明：跨应用相同邮箱独立邀请；token 重放拒绝；邀请投递失败不激活账号；访客升级不换 ID；停用/删除立即撤销会话；恢复不恢复旧令牌；跨应用用户组成员拒绝；组环拒绝；导入预检不写账号和关系表；重复确认不重复创建；公式注入被处理；Syncer 重试不重复、游标不越过失败页、大规模停用触发熔断、外部删除不会误删本地业务账号。

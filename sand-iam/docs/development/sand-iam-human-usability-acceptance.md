# SandIAM 三角色真人可用性验收

> 状态：实施中。本文是管理台体验和真实业务闭环的验收口径；[产品体验与闭环交付契约](sand-iam-product-experience-contract.md)定义固定产品语言和范围。代码检查、构建成功、接口成功和真人可用分别记录，不能互相替代。

## 1. 通过定义

核心流程必须只依赖页面标题、说明、字段提示、示例和错误恢复提示即可完成。操作手册用于补充背景，不得承担以下责任：解释数据库编号、翻译英文错误、要求操作者编写核心授权 JSON，或告诉操作者页面上没有展示的下一步。

以下条件全部满足才可标记“真人可用性验收通过”：

- 核心流程不手填数据库编号；关联对象按名称选择，并显示所属层级和系统代码。
- 客户主体、接入应用、应用环境和服务调用身份的名称、归属和系统代码含义无需猜测。
- 加载中、无权限、缺少上级对象、当前范围无数据、加载失败分别显示，不互相伪装。
- 必填字段、格式、对象停用、越组织、缺少授权和服务异常都给出可执行的恢复动作。
- 核心策略通过结构化控件表达；只有未冻结结构的高级可选配置允许使用 JSON。
- 凭证明文只出现一次，提供复制和安全交付提醒；关闭后页面不再保留明文。
- 每个安全操作的确认框说明对象、影响和恢复方式，不使用“调用真实接口”等开发术语。
- 总览七个模块使用固定用途说明，而非重复“适用角色”；用户状态只显示“已设置、尚未设置、进入页面确认、在接入应用中使用、暂时无法读取”。
- 未完成的接口契约、开发协作或内部状态不出现在用户界面；不能以“等待”“未冻结”之类的研发提示替代可用功能。
- 页面在 `1440×900`、`1280×720` 与窄屏都能滚到最后一个模块；不得由固定高度、隐藏溢出或嵌套滚动遮住内容。

## 2. 三类角色

### 平台超级管理员

1. 创建客户主体、接入应用和应用环境。
2. 登记服务调用身份；确认平台服务和服务动作目录。
3. 创建服务授权，签发凭证，完成 context 签发与校验。
4. 撤销凭证，确认旧凭证被拒绝并能从审计追溯。

### 受限组织管理员

1. 只能看到被委派客户主体下的数据。
2. 在允许范围内管理应用、环境、身份源、应用身份、用户类型、角色、资源和策略。
3. 使用角色或应用身份二选一创建策略，通过结构化 `equals` / `in` 条件配置范围。
4. 访问未委派客户主体或平台全局服务目录时被拒绝，并获得联系平台管理员的明确提示。

### 应用技术接入人员

1. 能区分服务调用身份、服务动作、服务受众和调用凭证。
2. 能确认 `audience` 必须由服务提供方给出，不能填写网址、模型名或临时备注。
3. 能安全接收一次性凭证，并验证正确调用、错误 audience、缺少授权和凭证撤销结果。
4. 能在审计中按主体、结果和对象追溯一次允许或拒绝。

## 3. 浏览器场景

- 视口：`1440×900`、`1280×720`。
- 页面：总览、客户主体、接入应用、应用环境、服务调用身份、服务授权、调用凭证、身份源、应用身份、角色、业务资源、策略、访问审计。
- 状态：加载、正常数据、无数据、缺上级对象、无权限、校验失败、后端异常、会话过期。
- 视觉：长名称、长系统代码、下拉选项层级、弹窗完整性、固定操作列、一次性凭证弹窗。
- 会话过期后必须离开受保护页面并清除可见的 SandIAM 业务内容；若可稳定复现旧内容残留，按 SandAdmin 宿主缺陷单独处理。

## 4. 业务闭环与清理

使用可识别的隔离验收前缀，记录创建对象、HTTP/业务结果、审计结果和清理状态。至少覆盖：

- 客户接入：客户主体 → 接入应用 → 应用环境 → 查询、修改、停用或恢复；
- 用户权限：身份源 → 用户/邀请/导入/同步 → 用户组 → 角色 → 资源 → 策略 → 允许与拒绝；
- 登录安全：认证设置 → 登录 → 会话 → MFA 或通行密钥 → 撤销 → 再次访问被拒绝；
- 系统调用：调用身份 → 服务授权 → 凭证 → 成功调用 → 无权调用 → 撤销；
- 接口治理：业务动作 → 接口目录 → 路由清单预检与确认 → 策略模拟 → 实际调用；
- 管理委派：委派 → 范围内操作 → 越权拒绝；
- 事件通知：订阅 → 触发变化 → 投递 → 失败重试 → 投递记录与排错。

每条均须证明页面、API、允许与拒绝、审计、撤销或恢复以及夹具清理。凭证、授权、客户主体等夹具按记录停用或清理，不删除不可变审计事实。外部系统未准备好时，可使用受控模拟服务完成协议闭环；不得以静态页面、构建或截图代替。

SandAI 真实业务 API 的允许、拒绝和审计归 A-01 双插件验收；SandIAM 自身通过不等于 A-01 已完成。

## 5. 证据分层

- **已检查**：源码、契约、字段和任务状态已核对。
- **已修改**：权威源码已更新，尚未证明运行页面采用该版本。
- **本地验证**：类型检查、构建、PHP 检查和纯函数测试通过。
- **正式 FLOW 验收**：三角色浏览器清单全部通过。
- **本地业务闭环**：签发、校验、拒绝、撤销和审计真实完成且夹具状态已核对。
- **可上线部署**：权威源码校验、包检查、宿主同步和回归通过；不等于已部署或线上验证。

# SandIAM 产品体验与闭环交付契约

> 状态：**源码已实现，动态验收待授权**。本契约规定开源 SandIAM 面向使用者的语言、总览、首次使用、入口和验收边界。它不新增业务 API、权限或数据库表；菜单和动态路由只复用现有权限。真实宿主、浏览器和七条业务闭环仍待单独授权后验收。

## 1. 行业中立与演示数据边界

SandIAM 是通用身份与访问管理插件。产品界面、说明书、通用接口示例和源代码注释都必须对任意行业成立。

- 特定行业的项目名称、组织名称、岗位名称和业务对象名称，只能作为**明确标注为“演示数据”**的记录值出现，例如某次受控验收夹具的客户主体名称或接入应用名称。
- 这些名称不得出现在功能名称、模块用途、操作引导、字段说明、占位文字、空态、错误提示、代码注释、通用 API 示例、默认配置或产品截图说明中。
- 演示数据必须可识别、可清理；删除后不应留下某一行业的产品含义。说明文字使用“客户主体”“接入应用”“应用用户”“业务对象”等通用词。

## 2. 总览的固定语言与状态

总览只说明“这个模块能帮你做什么”，不重复展示适用角色。七个模块固定使用下列用途文案：

| 模块 | 用途说明 |
| --- | --- |
| 客户与应用接入 | 登记谁在使用 SandIAM，以及哪些系统需要接入。 |
| 应用用户与权限 | 管理用户从哪里来、能进入哪些应用、可以做什么。 |
| 认证与会话 | 设置登录方式和安全要求，管理登录状态。 |
| 接口与访问控制 | 控制系统之间如何连接，以及可以调用哪些能力。 |
| 管理范围 | 把指定客户或应用的管理工作交给合适的管理员。 |
| 事件通知 | 把用户和权限变化通知给业务系统，并查看是否送达。 |
| 审计与排错 | 查询谁在什么时候做了什么，并处理异常。 |

总览只能使用以下用户可理解的状态。状态的依据必须真实，不能由页面猜测：

| 状态 | 使用条件 | 必须给出的下一步 |
| --- | --- | --- |
| 已设置 | 已从可用接口可靠读到所需配置。 | 可查看或修改。 |
| 尚未设置 | 已从可用接口可靠确认当前没有配置。 | 现在设置。 |
| 进入页面确认 | 总览无法可靠判断完成情况。 | 打开页面查看。 |
| 在接入应用中使用 | 该能力属于应用用户或协议运行面，不是后台配置页。 | 查看接入说明或打开独立入口。 |
| 暂时无法读取 | 请求失败、会话失效或没有读取权限。 | 重试、重新登录或联系管理员。 |

禁止在产品页面出现“等待 Codex”“不编造接口”“冻结 DTO”“运行面”“候选实现”“contractStatus”等开发词汇。未完成能力不应作为可点击的半成品入口；若必须说明，应写明对使用者有用的替代路径和当前可执行动作。

## 3. 第一次使用：单页连续向导

管理端新增 `/sand-iam/getting-started`，标题为“第一次使用”。它是一个单页连续向导，而非另一套业务逻辑：复用已有表单、API、权限和校验；**不新增数据库表**。

共同步骤固定为：

1. 创建客户主体。
2. 创建接入应用。
3. 创建应用环境。
4. 选择接下来的目标（可多选）：让员工登录并分配权限、让系统调用接口、接收用户和权限变化通知。
5. 仅展示所选目标需要的后续步骤，并可返回修改前一步。

每一步必须按同一顺序呈现：**这一步解决什么问题 → 开始前准备什么 → 在页面上怎么做 → 怎样确认成功 → 常见错误如何处理 → 下一步去哪里**。保存后必须读取实际结果；返回向导时恢复已有记录，不重复创建对象。没有权限、缺少上级对象、校验失败、冲突、网络失败和服务错误必须分别给出人话恢复办法。

## 4. 页面、入口与应用用户边界

- 总览使用一个明确的页面滚动区域；不得以固定高度、隐藏溢出或卡片内滚动使最后一行无法到达。`1440×900`、`1280×720` 和窄屏均须可看到每个模块的完整内容和操作。
- 每个可点击的管理入口必须同时具备已发布页面、菜单/动态路由、访问权限和真实后端能力；缺任一项即不得作为可点击入口。自动检查必须覆盖此规则，防止 404。
- 应用用户会话、MFA、通行密钥、CAS 确认等应用用户功能不伪装为 SandAdmin 配置页；它们使用独立应用入口和应用用户会话，不使用宿主后台会话。
- 前端不得自行推断授权允许/拒绝、投递成功或配置完成。接口未提供可靠结论时使用“进入页面确认”或“暂时无法读取”。

## 5. 七条业务闭环与证据层级

以下每条均须实际完成“页面 → API → 权限允许/拒绝 → 审计 → 撤销或恢复 → 夹具清理”。外部依赖可使用受控模拟服务，但不能只验证静态页面或构建。

1. 客户主体 → 接入应用 → 应用环境 → 查询、修改、停用或恢复。
2. 身份源 → 用户/邀请/导入/同步 → 用户组 → 角色 → 资源 → 策略 → 实际允许与拒绝。
3. 认证设置 → 登录 → 会话 → MFA 或通行密钥 → 撤销 → 再次访问被拒绝。
4. 调用身份 → 服务授权 → 凭证 → 成功调用 → 无权调用 → 凭证撤销。
5. OAuth/OIDC PKCE → CAS → 应用业务动作 → 接口目录 → 路由绑定 → 路由清单预检与确认 → 策略模拟 → 实际调用结果与审计一致。
6. 管理委派 → 被委派管理员在范围内操作 → 越权被拒绝并可追溯。
7. 通用业务/安全事件订阅 → 触发变化 → Webhook 成功投递 → 失败重试 → 投递记录 → 审计与排错；不以验证码、邀请、恢复等认证事务消息代替。

第 5 链不得预置授权码或 CAS Ticket：必须实际完成 OAuth authorize/login/interaction、PKCE code 换 token、CAS login/应用用户确认/Ticket 校验，再登记业务动作和接口目录、绑定路由、完成清单预检与确认、执行同一策略的模拟与真实调用。允许与拒绝结果、审计、撤销后拒绝和 OAuth/CAS/API 治理对象清理必须属于同一轮可追溯夹具。

证据必须分层报告：**静态检查**（类型、构建、契约）、**宿主验收**（已安装页面和路由）、**本地业务闭环**（上述实际操作与清理）、**可部署性**（包、升级、回滚和运行基线）。任何前一层通过都不替代后一层。

## 6. Cursor 与 Codex 协作

- Cursor 只修改 `sand-iam/sandadmin-artd/src/views/plugin/sand-iam/**` 及对应前端测试；不得修改 PHP、SQL、菜单、权限码、宿主或全局 hooks。
- Codex 负责接口、权限、菜单与路由契约、后端、验收结论和返工决定；Cursor 的完成是待验收成果，不是最终通过。
- Cursor 任务按依赖顺序执行。Codex 验收失败时，将失败证据写回同一任务并返工；未通过前不开放依赖它的下一项。
- 2026-08-28/31 的 Cursor Autopilot 与 DETECT 开启记录仅是历史协作快照，不表示当前 Agent、开关或 watcher 状态。Cursor 完成项仍须 Codex 独立验收；未通过前不得上调正式 FLOW。

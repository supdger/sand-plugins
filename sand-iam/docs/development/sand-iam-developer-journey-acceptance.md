# SandIAM 开发者旅程验收

> 口径日期：2026-08-23。本文把“比直接使用 Casdoor 更顺手”改成可计时、可失败、可复核的验收问题。目标值不是已通过结论；必须由同一名具备 Webman 基础经验但未参与两边实现的开发者，在同等干净环境分别执行并保留证据后才能比较。

> 当前 FLOW 严格口径为 **8/9、20/20、0/7、0/4、0/8**，即 **28/48（58.3%）**；030 机器调用约束、P14 目录同步运行与 P19 初始化草稿均已按各自模块证据计分，SandLicense 仍是独立领域边界。本文只冻结旅程方法，不提供任何一次真实旅程通过证据，因此不能提升正式验收或业务闭环。静态与隔离实现证据不替代当前候选的 PostgreSQL 生命周期、真实宿主和浏览器闭环。

## 1. 统一计时规则

计时从开发者拿到可访问地址、文档首页和规定输入开始，到最后一个成功证据落盘结束。预装软件、登录、网络等待和供应商故障单独计时，但不得从失败次数中删除。

每次验收记录：执行人、版本/提交、宿主版本、浏览器和 SDK 版本、开始/结束时间、人工操作数、命令数、失败次数、查阅页面、请求 ID、截图/日志位置和清理结果。密码、Token、验证码、私钥和凭证明文不得进入证据。

每个 HTTP 请求必须使用唯一 `request_id`；允许请求记为 `allow_request_id`，拒绝请求记为 `deny_request_id`，两者不得复用。一次旅程验收另生成独立 `acceptance_run_id` 聚合所有请求和证据；它只用于验收报告关联，不作为 SandIAM 授权输入，也不参与任何幂等键。

“人工操作”指一次有业务意义的提交、复制配置、执行命令或修改业务代码；浏览文档和只读查看不计入，但必须记录查阅页面。发生以下任一情况即失败：需要未记载的内部知识、跨应用数据可见、拒绝时没有稳定错误和审计、必须直接改数据库、秘密进入日志、无法清理夹具，或目标时间内没有形成最终证据。

Casdoor 对照必须使用其官方支持的安装和 SDK/协议文档，选择能达到同一业务结果的最短公开流程；不能故意选择更复杂的 Casdoor 路径，也不能把 SandIAM 预制夹具算作免费步骤。

## 2. 旅程一：Webman 接口登记到允许、拒绝和审计

### 输入

- 一个已登录但没有预制业务对象的 SandAdmin 管理账号；
- 一个可运行的最小 Webman API，含 `GET /matters/{id}` 和 `POST /matters`；
- 一份只含方法、路由模板、中文名称和风险等级的 OpenAPI 文件；
- 两个测试身份：一人应允许读取，另一人应被拒绝；
- SandIAM PHP SDK/中间件文档入口。

### 操作与目标

目标为 **20 分钟内、最多 8 次人工操作、业务代码改动不超过一个中间件接入点**：

1. 创建或选择客户主体、接入应用和测试环境；
2. 导入 OpenAPI 接口目录；
3. 将两条路由绑定到稳定的 `matter.read`、`matter.create` 语义动作；
4. 建立角色/策略和数据范围；
5. 在 Webman 接入 SDK/中间件；
6. 以允许身份请求读接口并得到成功；
7. 以拒绝身份请求同一路由并得到稳定拒绝；
8. 分别用 `allow_request_id`、`deny_request_id` 查到允许和拒绝审计，并用同一 `acceptance_run_id` 归入本次验收。

### 必须证据

- OpenAPI 导入摘要、路由绑定和语义动作截图或脱敏响应；
- 允许/拒绝 HTTP 状态、稳定错误码、互不相同的 `allow_request_id` 与 `deny_request_id`，以及聚合本次验收的 `acceptance_run_id`；
- 审计中可读的应用、身份、资源、动作、结果和拒绝原因；
- 将 URL 从 `/matters/{id}` 改成 `/v2/matters/{id}` 后，只改路由绑定、不改策略键即可再次得到相同决策。

### 错误与清理

路由冲突、未绑定动作、应用停用、跨应用身份和无策略必须关闭失败。验收结束后删除或停用测试应用、策略和路由夹具，确认没有凭证、授权和审计以外的残留；审计按验收环境保留规则处理。

### Casdoor 对照

在 Casdoor 中用官方权限模型和公开 SDK/中间件完成相同两路由、两身份、允许/拒绝和可追踪记录。分别记录总时间、人工操作数、业务代码改动点、URL 版本变化时是否要改长期权限键。SandIAM 只有在结果等价、没有放宽安全门禁且时间/操作数至少一项更少、另一项不增加时，才可写“本旅程更顺手”。

## 3. 旅程二：人类注册、登录、MFA 到业务 API

### 输入

- 一个没有测试用户的接入应用，允许邮箱注册并要求验证；
- 可收取测试验证码的受控邮箱/消息假驱动；
- 一个标准 TOTP 验证器和干净浏览器配置；
- 一个要求 `profile.read` 的最小业务 API。

### 操作与目标

目标为 **10 分钟内、最多 9 次人工操作、不进入 SandAdmin 后台完成用户侧步骤**：

1. 打开应用登录入口并注册；
2. 输入验证码完成邮箱验证；
3. 首次登录并打开安全设置；
4. 绑定 TOTP，并保存一次性恢复码；
5. 登出后重新登录；
6. 完成 MFA challenge；
7. 使用访问令牌调用 `profile.read` 业务 API；
8. 撤销当前会话；
9. 再次调用业务 API并得到稳定拒绝，同时查到登录、MFA、授权和撤销审计。

### 必须证据

- 浏览器截图覆盖注册、验证、登录、MFA、会话和可恢复错误，不显示秘密；
- 成功 API、撤销后拒绝 API、错误码、各 HTTP 请求唯一的 `request_id` 与审计关联，并以独立 `acceptance_run_id` 聚合本次验收；
- 跨应用复用相同邮箱时形成独立账号，不能自动合并；
- 过期验证码、错误 TOTP、重放 challenge 和已撤销会话均稳定失败。

### 错误与清理

任何一步需要后台账号代替应用用户、直接写表、向用户展示内部 ID 或无法说明下一步，都判定失败。结束后撤销会话和 MFA 因子，清理测试身份、验证码和消息夹具，确认无明文恢复码或 Token 残留。

### Casdoor 对照

在相同邮箱、TOTP、浏览器和业务 API 条件下，通过 Casdoor 官方用户门户和 OIDC/SDK 完成相同流程，记录首次可发现入口、总时间、人工操作数、失败恢复次数和业务代码改动点。没有双方实测前，只能写“目标不劣于 Casdoor”，不能写“已经更好”。

## 4. 旅程三：机器凭证到 SandAI 语义动作

### 输入

- 一个已登记的客户主体、接入应用和测试环境；
- 已由 SandAI 清单登记的 `sand_ai.chat.complete` 动作；
- 一个最小服务端调用程序；
- 一名仅拥有该应用管理范围的应用管理员。

### 操作与目标

目标为 **15 分钟内、最多 8 次人工操作、凭证明文只出现一次**：

1. 创建工作负载客户端；
2. 向测试环境授予 `sand_ai.chat.complete`，设置正确 audience 和短有效期；
3. 签发并安全保存一次性凭证；
4. 用凭证取得短期机器上下文；
5. 调用 SandAI chat action 并成功；
6. 用错误 audience 或未授权 action 调用并稳定拒绝；
7. 撤销凭证后再次取得上下文并稳定拒绝；
8. 通过各 HTTP 请求唯一的 `request_id` 在 SandIAM 与 SandAI 两侧核对允许、拒绝和撤销审计，并以独立 `acceptance_run_id` 聚合本次验收。

### 必须证据

- 名称优先的客户端、环境、服务和动作配置；
- 凭证仅一次展示、日志脱敏、短期上下文的 audience/action/expiry；
- SandAI 允许与至少两个拒绝响应、稳定错误码、各请求在双侧一致且请求之间互不复用的 `request_id`，以及聚合本次验收的 `acceptance_run_id`；
- 应用管理员无法为自己增加其他应用或其他动作范围。

### 错误与清理

错误 audience、动作、环境、过期授权、停用应用和撤销凭证必须关闭失败。结束后撤销并删除测试凭证材料，停用临时客户端/授权，确认不能再次签发上下文；不删除依法或按策略保留的审计。

### Casdoor 对照

Casdoor 没有与 SandAI 完全相同的 Sand 原生 `service → action → environment → workload client` 模型，因此对照结果定义为“让机器客户端只能调用一个语义动作，并能审计允许、拒绝和撤销”的最短官方方案。记录是否需要把 HTTP URL 作为长期权限键、是否需要业务侧自建额度/环境映射、总时间、人工操作数和代码改动。差异必须如实列出，不能把模型不同直接写成 SandIAM 已胜出。

## 5. 判定和发布用语

- 三条旅程均未实测时：只能写“已定义开发者体验目标”。
- 单条双方实测通过时：只能对该旅程写结论，并附原始证据。
- 只有三条旅程都由独立开发者重复至少两轮，且 SandIAM 没有新增高风险人工步骤，才可在产品总述中写“在已测旅程上比直接使用 Casdoor 更顺手”。
- 任何构建、单元测试或 API 自测都不能替代真实管理界面、用户门户、业务 API 和清理证据。

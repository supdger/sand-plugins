# 应用用户操作

应用用户从接入应用提供的独立入口登录，不使用 SandAdmin 后台账号。

## 登录与恢复

- 只从应用确认的 HTTPS 地址进入；不要通过聊天或搜索结果中的临时链接输入密码。
- 登录失败时先核对应用和账号范围。连续失败触发锁定后，按页面提示等待或联系应用管理员。
- 忘记密码时使用一次性恢复流程；恢复链接、验证码和恢复码不得转发。

## 会话与安全设置

在自助门户中查看当前和历史会话，撤销不认识的设备。修改密码后重新检查会话列表。
启用 MFA 或 Passkey 时保存一次性恢复码；设备丢失或认证器异常时使用受控恢复流程，
不要要求管理员读取密码、密钥或恢复码。
若提交 TOTP 绑定、确认或恢复码再生成后页面提示网络超时，不要立即发起新的操作；客户端应先以相同内容和同一请求标识重试。重放响应不会再次显示秘密，无法确认是否已安全保存时应按页面提供的重新绑定或再次生成流程处理。
完成 Passkey 注册时若页面在提交后超时，应保持同一 Credential 响应和同一请求标识重试；服务只确认首次注册结果，不会重复添加设备。不要重新生成请求标识后重放已完成的 challenge。
MFA 或 Passkey 登录已提交但令牌响应丢失时，仅在 30 秒内以完全相同的 challenge、验证响应、来源网络和请求标识重试；成功恢复后立即采用返回的新会话。超过窗口或被拒绝时停止自动重试并重新登录，不要换 request id 重放旧 challenge。
密码登录本身若在成功提交后丢失会话或 MFA challenge 响应，也应在 30 秒内保持应用、账号、密码、验证码、来源网络、user agent 和请求标识完全一致后重试；服务会恢复首次结果，不会再次创建会话或 challenge。若返回登录重试不可用，请用新请求标识重新开始登录。
Passkey 登录获取认证选项时也要为一次认证意图固定请求标识；响应超时后以相同来源网络重试会得到同一个 challenge，且不会重复占用 options 限流。若该 challenge 已被使用或过期，请换一个新请求标识重新开始认证。

## 连接身份

连接外部身份前确认身份源名称和目标应用。解绑前确保仍有其他可用登录方式。
若系统提示身份冲突，不要创建重复账号；联系应用管理员核对身份源实例和应用归属。

## 发现异常

立即撤销可疑会话并修改密码；若凭证、恢复码或设备可能泄露，撤销对应认证器。
向管理员提供操作时间、应用名称、错误码和脱敏截图，不要发送令牌、验证码或个人敏感数据。

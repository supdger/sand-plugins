# 第一次使用 SandIAM

本页写给应用管理员，适用于 `0.8.3` 源码候选。先在 SandIAM 总览的“这次要完成什么？”选择当前目标，再核对账号权限与所选应用；已有应用、身份、登录或其他配置时复用它们。确需新应用且具有登记权限时，再参考下方登记说明。缺少权限请对应管理员办理，不通过新建应用绕过管理范围。日常权限配置和完整例子见[管理员说明](sand-iam-operator-guide.md)；应用开发者从[业务接入](application-integration.md)开始。

## 从当前目标继续

1. 在总览选择要办的事：已有登录时可直接配置权限和数据范围；后端调用服务无需先开通员工账号；企业登录与目录同步按实际需要分别办理。
2. 选择已有可管理应用，核对所属客户主体；系统调用还要核对环境。当前账号不能浏览或办理某步时，由获授权负责人完成，不重复创建对象。
3. 按当前步骤说明准备输入、保存并核对状态。角色可按目标需要选择；为同一应用增加第二个目标时保留应用与已有配置。
4. 在接入应用或服务中验证实际结果，再按请求号核对审计。“继续”、已有记录、保存成功与策略模拟不代表真实业务通过。

本候选尚未公开发布。宿主需构建并激活管理端源码，才会出现目标引导；本说明不代表宿主安装或全部目标的端到端验收已完成。

## 先判断这次能做到哪里

| 你已有的条件 | 可以完成什么 | 还需谁配合 |
| --- | --- | --- |
| 已安装 SandIAM，能登录 SandAdmin 并有管理权限 | 登记公司、应用、环境；保存账号与权限配置 | 平台管理员确认菜单权限和管理范围 |
| 门户和邀请发送已配置，或应用已开放注册 | 员工设置自己的账号密码并登录账户门户 | 运维确认入口与消息服务，员工完成注册或邀请 |
| 业务系统已接入 SandIAM，已有测试对象 | 验证某员工可以访问、其他员工被拒绝，撤权后不能访问 | 应用开发者提供业务入口、资源动作和数据字段 |
| 已部署目标服务，并已登记服务与动作 | 签发调用凭证，由应用后端发起真实调用 | 服务提供方提供配置单，应用技术负责人接入调用 |

保存配置与策略模拟都可以在后台完成。员工在真实业务系统中的权限、服务调用是否成功，需要上述对应环境；缺少条件时在交接点停止，不猜业务字段或服务受众。

## 确需新应用时，登记公司、系统和环境

- **客户主体**：独立公司或客户。公司自己使用也要登记自己的公司。公司的部门不在这里登记。
- **接入应用**：该公司需要使用身份或权限服务的产品、系统，例如工作项系统；不是一个员工。
- **应用环境**：该系统的测试、生产等运行环境。应用用户账号按应用隔离，不要把环境名称理解为另一个用户目录。
- **系统代码**：给接口引用的稳定简称。新接入可由应用技术负责人约定；已接入系统应沿用其配置中的值，不能随意换名。

下面是一套**演示填写值**，不代表宿主已有这些记录：

| 页面 | 名称 | 系统代码 | 由谁确认 |
| --- | --- | --- | --- |
| 客户主体 | 示例公司 | `example-company` | 公司/客户负责人 |
| 接入应用 | 工作项系统 | `work-items` | 应用负责人和开发者 |
| 应用环境 | 测试环境 | `test` | 运维负责人 |

代码使用小写字母、数字、短横线或下划线，2–64 位，以字母或数字开头。客户主体代码全平台唯一；应用代码在公司内唯一；环境代码在应用内唯一。创建后不改代码，名称可以按权限编辑。

## 完成基础登记

1. 登录 SandAdmin，打开 **SandIAM 身份与访问 → 第一次使用**。看不到入口时，让平台管理员检查你的菜单权限与公司/应用管理范围。
2. 创建客户主体，按上表填写公司名称、代码；自用时填自己的公司，不填部门、员工或订单。
3. 创建接入应用，选择刚创建的公司，填写应用名称、代码。
4. 创建应用环境，选择该应用，填写测试环境名称、代码。
5. 保存后重新打开记录，确认“示例公司 → 工作项系统 → 测试环境”归属正确。已有对应记录时选用它，不重复创建。

这一步只完成接入登记。下面按目标继续，每页核对当前公司、应用和环境；列表里有记录不代表这个应用已全部配置。

## 目标一：开通一个员工并给他权限

先向运维取得该应用的账户门户地址，向应用负责人确认开通方式：

| 开通方式 | 管理员做什么 | 员工做什么 |
| --- | --- | --- |
| 邀请开通 | 确认邀请发送可用，在 **用户邀请** 选择应用、邮箱或手机并发送 | 从收到的邀请设置账号密码，再登录 |
| 开放注册 | 在 **认证设置** 开放注册，核对应用登录设置中的密码登录与注册字段 | 从本应用账户门户注册，按要求验证邮箱/手机，再登录 |
| 使用已有企业账号 | 请企业账号系统负责人提供协议、地址及应用配置，由接入工程师配置身份源 | 使用应用提供的企业登录入口 |

本地密码账号不要求先配置企业身份源、目录同步或导入。后台 **应用用户 → 新建用户** 只登记身份，不设置本地密码；不要将它当作已能登录的账号，也不要先建同代码身份再注册同名账号。

邀请发送所需的入口、密钥和消息配置由运维处理，见[配置参考](configuration-reference.md#应用体验消息与身份生命周期)。管理员不应替员工设置或收集密码。

按[管理员说明中的工作项例子](sand-iam-operator-guide.md#给两名员工开通账号并分配工作项权限)开通小林和小周：小林获得明确权限，小周保持无权。然后由员工打开应用负责人提供的**业务系统地址**验证允许与拒绝。账户门户只管理账号和安全信息，不会自动出现工作项列表。没有业务系统时可先验证门户登录，把权限验证交给应用开发者。

## 目标二：让后端调用一个服务

先让服务提供方交付服务代码、受众、动作和调用地址，再创建调用身份、授权与凭证。受众是目标服务约定的识别字符串，例如现有文档处理示例使用 `provider-b`，不是服务网址，也不由管理员猜。

按[管理员说明的服务配置单](sand-iam-operator-guide.md#第四条调用身份服务授权凭证和调用)填写。凭证交给指定应用、环境的技术负责人保管，真实调用由应用后端执行。验收应能看到成功调用、无权调用被拒绝、撤销后旧凭证不能使用；只有“凭证已签发”还未接通服务。

## 目标三：接收用户或权限变化通知

向接收系统负责人取得 HTTPS 地址、事件范围及联系人。按[事件通知步骤](sand-iam-operator-guide.md#第七条事件订阅成功投递失败重试和审计)保存后，触发一次测试变化并核对接收端结果；投递失败先修正接收端，再从投递记录重试。

## 遇到问题

| 情况 | 下一步 |
| --- | --- |
| 没有菜单、按钮，或没有权限 | 平台管理员分别检查菜单权限与公司/应用管理范围，不借用他人账号 |
| 看不到上级记录 | 确认上一步已保存、启用且在自己范围内；重新选择正确公司和应用 |
| 代码冲突 | 核对是否已有同一对象；选用现有记录或与应用负责人确认新代码 |
| 用户创建了却不能登录 | 确认他完成邀请或注册并设置密码；核对应用代码、登录方式、账号状态 |
| 邀请或验证码未送达 | 查邀请/消息状态，让运维检查发送配置；不重复建用户、不转发验证码 |
| 调用被拒绝 | 技术负责人核对当前环境、受众、服务动作及凭证状态，再查对应访问审计 |
| 请求失败或结果不确定 | 重新读取记录确认是否保存；仍失败时提供页面、时间和错误信息给管理员，不反复提交 |

成功后再撤销一次测试授权或凭证，确认旧访问被拒绝。恢复用户并不恢复旧会话、旧令牌或已移除权限；重新授权、登录或签发凭证后再验证。清理只处理本次演示记录，保留审计。

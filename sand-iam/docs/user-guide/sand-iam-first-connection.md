# 第一次使用 SandIAM

> 需要完整的日常操作、七条操作链、撤销、审计和故障处理时，请看[SandIAM 手把手使用说明](sand-iam-operator-guide.md)。

> 给第一次负责接入的管理员。照着本页做，不需要编程，也不需要知道数据库、接口或内部编号。本页与管理端“第一次使用”向导采用同一顺序；没有看到对应按钮时，先按“遇到问题”处理，不要猜测或绕过权限。

## 你要完成什么

先把“谁在用、哪个系统在用、在哪个环境使用”登记清楚：

```text
客户主体
└── 接入应用
    └── 应用环境
```

之后按你的实际目标继续：

- 让员工登录并分配权限；
- 让系统调用接口；
- 接收用户和权限变化通知。

这三个目标可以同时选择。只做前面三步也可以安全停止，稍后再继续。

## 先准备这些信息

| 要准备的内容 | 谁能提供 |
| --- | --- |
| 客户主体的正式名称 | 业务负责人或客户负责人 |
| 接入应用的名称 | 应用负责人 |
| 要使用的环境，例如开发、测试或生产 | 应用运维负责人 |
| 若系统需要调用接口：后端调用身份名称、目标服务受众和所需动作 | 应用技术负责人和服务提供方 |
| 若需要员工登录：用户来源、初始管理员、可管理的业务对象和规则 | 应用负责人 |
| 若需要事件通知：接收地址、事件范围和接收方联系人 | 接收系统负责人 |

不要把个人姓名、业务订单、项目编号或临时验收编号当作客户主体、应用或环境名称。

### 演示数据仅供识别格式

如果你在测试环境看到“演示客户主体”或“演示接入应用”，它们只用于说明填写格式，不代表 SandIAM 只服务某一类业务。日常操作请使用你自己的客户主体和应用名称。

## 用管理端向导完成前三步

1. 登录 SandAdmin 后，打开 **SandIAM 身份与访问**。
2. 打开 **第一次使用**。如果看不到入口，请让平台管理员授予 SandIAM 菜单和客户主体管理权限。
3. 在“创建客户主体”填写给人看的名称和系统代码。系统代码是给系统稳定引用的短代码；创建后通常不能修改。
4. 保存后确认页面显示“已保存”，并能看到刚创建的名称。
5. 继续“创建接入应用”，选择刚创建的客户主体，再填写应用名称和系统代码。
6. 保存后确认所属客户主体正确；如果选错，先修正归属，再继续。
7. 继续“创建应用环境”，选择接入应用，填写环境名称和系统代码。
8. 保存后，返回向导确认三项都显示为已设置。

成功标志是：你能按“客户主体 → 接入应用 → 应用环境”的层级找到刚创建的记录。仅看到一个弹窗提示不算完成。

## 根据目标继续

### 让员工登录并分配权限

在向导中选择“让员工登录并分配权限”，依次完成：

1. 选择或创建身份源，说明用户从哪里来。
2. 创建或邀请应用用户；需要批量处理时先预检导入结果，再确认导入。
3. 建立用户组、角色和业务资源。
4. 用结构化方式设置策略：谁、可以对什么、做什么操作。
5. 让一名允许访问的用户登录，再用一名没有权限的用户验证拒绝结果。
6. 在审计中查看两次操作，并确认停用用户或撤销授权后访问会被拒绝。

成功标志是允许和拒绝都符合预期，并且可以在审计中查到原因。不要以“页面上能看到角色”代替实际登录验证。

### 让系统调用接口

在向导中选择“让系统调用接口”，依次完成：

1. 创建服务调用身份。它代表应用后端，不代表某个员工。
2. 由服务提供方确认服务动作和服务受众；服务受众不是网址、模型名或备注。
3. 创建服务授权，只授予实际需要的动作。
4. 签发调用凭证。明文只显示一次，立即交给应用技术负责人保存到受控密钥库。
5. 由应用技术负责人做一次成功调用，并再做一次无权或错误受众调用。
6. 撤销凭证后再次调用，确认被拒绝；随后在审计中核对签发、调用和撤销记录。

成功标志是正确调用成功、错误调用被拒绝、撤销后旧凭证失效。不要把凭证写进聊天、工单、截图、代码仓库或浏览器收藏夹。

### 接收用户和权限变化通知

在向导中选择“接收用户和权限变化通知”，依次完成：

1. 创建事件通知，选择接入应用、接收地址和需要的事件。
2. 保存后触发一次受控的用户或权限变化。
3. 查看投递记录，确认接收方成功收到通知。
4. 用受控接收端制造一次失败，确认系统给出可理解的失败原因和重试入口。
5. 重试成功后，在投递记录和审计中核对全过程。

成功标志是成功投递、失败重试和审计记录都能对上。不要只因为通知配置已保存就认定接收端可用。

## 遇到问题时这样处理

| 你看到的情况 | 先做什么 |
| --- | --- |
| 看不到菜单、新建按钮或列表 | 重新登录；仍无权限时请平台管理员检查你的 SandIAM 权限和管理范围。 |
| 不能选择客户主体、应用或环境 | 确认上一步已保存且处于可用状态，并确认你拥有该范围。 |
| 提示与现有配置冲突 | 不要重建相似记录；打开已有记录核对名称、系统代码和归属。 |
| 网络失败或暂时无法读取 | 重试；持续失败时记录页面提示和操作时间，交给平台管理员排查。 |
| 系统调用被拒绝 | 核对环境、调用身份、服务动作和服务受众，再查看审计。 |
| 凭证泄露或交给了错误的人 | 立即撤销或轮换，并通知应用技术负责人更新受控密钥库。 |

## 你何时可以停止

你可以在以下任一位置停止：

- 已完成客户主体、接入应用和应用环境，尚未需要员工登录、接口调用或事件通知；
- 已完成所选目标，并通过了对应的成功、拒绝、撤销或重试检查；
- 当前缺少业务规则、服务受众、接收地址或权限时，记录缺少什么并交给相应负责人。

不要为“把向导走完”而猜测业务规则。SandIAM 负责通用身份、权限、授权和审计；具体业务对象及业务规则由接入应用定义。

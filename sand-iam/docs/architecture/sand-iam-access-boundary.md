# SandIAM 独立插件与服务接入边界

> 状态：需求与架构边界已确认；首期功能需求见[SandIAM 产品需求](../product/sand-iam-product-requirements.md)。适用范围：Sand 平台、SandIAM、SandAI 和任意接入应用。

## 1. 产品关系

SandAdmin 是运行宿主和平台后台入口；SandIAM 是同一宿主内的通用身份、授权与服务访问控制插件。SandAI 可以作为被授权调用的服务之一，但不是 SandIAM 的安装或运行前提。插件依托宿主运行，不等于接入应用的最终用户必须复用宿主后台账号。

| 主体 | 定义 | 是否属于 SandIAM 管理范围 |
| --- | --- | --- |
| 平台超级管理员 | 具有平台级治理权限的 SandAdmin 系统用户 | 账号由 SandAdmin 管理，用于平台后台与插件治理 |
| 平台客户主体 | 接入平台的独立客户或业务主体 | 是，建模为 `organization` |
| 接入应用 | 客户主体运行并调用平台能力的系统 | 是，建模为 `application` |
| 服务调用身份 | 接入应用后端调用已登记服务的机器身份 | 是，建模为 `workload_client` |
| 应用用户 | 接入应用的最终用户或业务管理员 | 是，SandIAM 提供身份目录、身份源绑定、用户类型、角色、策略、数据范围和审计能力；具体规则由接入应用定义 |

客户主体、接入应用、服务调用身份、宿主后台账号与应用用户是不同对象。宿主后台账号和应用用户属于独立身份域，认证凭据、权限与审计记录不能混用，也不能自动互相转换。

每个应用拥有独立的 identity 与 identity provider。不同应用的账号、凭据、会话和授权关系不得因外部标识相同而自动合并；应用间单点登录只能通过显式联合登录配置建立。

## 2. 权威层级

```text
platform operator
└── organization（客户主体）
    └── application（接入应用）
        └── environment（开发 / 测试 / 生产）
            └── workload_client（服务调用身份）
                └── service_grant（服务授权）
                    └── service_action（可调用动作）
```

服务授权使用稳定的语义动作代码，不能直接使用 HTTP 路径作为权限标识。URL 可以升级，语义服务动作必须保持稳定。

## 3. 调用与控制流程

1. 平台管理员创建或审核客户主体。
2. 在客户主体下登记接入应用，并创建开发、测试或生产环境。
3. 为需要调用服务的环境创建服务调用身份；凭证只展示一次，支持轮换和撤销。
4. 平台管理员将允许的服务动作授予调用身份，并配置服务受众、限额、数据等级、网络和有效期约束。
5. 接入应用后端以服务调用身份从 SandIAM 获取短期调用上下文，再调用已授权服务。
6. 服务提供方验证应用、环境、服务受众、服务动作和策略后执行能力。
7. SandIAM 记录身份、授权、拒绝与撤销审计；服务提供方记录自身的执行审计。

应用用户可使用 SandIAM 的通用身份与授权能力；用户类型、登录方式、业务对象与规则由接入应用配置和保存。SandIAM 不接管业务实体或业务规则。

## 4. 管理面职责

| 管理动作 | 入口与权威 |
| --- | --- |
| 平台后台账号、插件菜单与全局治理 | SandAdmin 宿主 |
| 应用用户、用户类型、登录、角色与数据范围 | SandIAM 提供通用能力；接入应用配置业务规则并保存业务实体 |
| 创建客户主体、应用、环境和服务调用身份 | SandIAM 管理面 |
| 签发、轮换、撤销调用凭证 | SandIAM 管理面 |
| 注册服务动作并授权给接入应用 | SandIAM 管理面 |
| 服务的供应商配置、能力路由与执行观测 | 对应服务插件或服务提供方 |
| 查看某应用获得的服务授权 | 服务提供方可以只读展示；修改必须跳转 SandIAM |

服务提供方不能创建平行的 `application`、`workload_client`、`credential` 或 `service_grant` 权威表，也不能直接跨库依赖 SandIAM。运行时通过适配器消费 SandIAM 签发并验证的上下文；同机部署和远程部署只更换适配器，不改变领域逻辑。

## 5. 插件宿主和实例边界

- SandAdmin 是唯一宿主；SandIAM 完整插件包只依赖宿主。
- 在未安装任何其他插件时，身份、组织、应用、客户端、凭证、策略、数据范围和审计仍可独立使用。
- SandIAM 提供通用能力，不内置任何行业或接入应用的用户类型、资源和规则。
- 使用 SandIAM 的接入应用不安装或复制第二套 SandIAM；其业务实体仍由接入应用保存。

## 6. 迁移要求

服务插件历史上的自包含 application、environment、credential 管理接口只能作为受控兼容基线，不得扩展为第二套 IAM。迁移必须覆盖：

1. 现有 application/environment 到 SandIAM 稳定标识的映射；
2. 旧凭证的受控轮换、过渡期和撤销；
3. 资源对 `application_id`、`environment_id` 的引用兼容；
4. 管理页入口、权限代码和审计归属调整；
5. 双读或兼容适配器的退出条件、回滚路径和真实调用验收。

迁移文档必须区分“已确认的目标架构”和“仍在运行的兼容接口”，不能把架构决定误报为已经完成的数据或代码迁移。

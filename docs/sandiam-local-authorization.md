# SandIAM 本地开发与验收持续授权

来源：用户在展示 LDAPS 修复提交与 v20 外部验收两批操作后明确要求
“修复这个问题，以后不要向我申请”。本授权限本工作区 SandIAM 的本地开发、
候选交付及验收；用户后续撤销或收窄时以最新指令为准。

## 已批准范围

- 在 `sand-iam/**` 编辑、构建、回归、修复复测；核对完整差异后仅暂存并本地提交
  本任务相关文件，不包含其他人的修改。生成 clean commit 候选及签名；
  使用任务专用签名密钥或已有明确授权用途的密钥，不读取无关凭据。
- 通过既有受控脚本导出至 `sandadmin-demo-host`，通过 SandPackage 备份、
  卸载、fresh install、失败恢复及运行载荷对账，必要时重载 Webman。
  执行破坏步骤前核实目标与备份可恢复；不因此要求用户重批同一范围。
- 在现有 `sandadmin` PostgreSQL 中执行当前候选所需的迁移和固定前缀验收夹具，
  完成 OIDC、SCIM、CAS、RADIUS 等七协议真实互操作、证据采集及同候选
  24 小时稳定性验证。仅使用受控验收端点与测试身份，不对真实第三方用户产生副作用。
- 仅通过 Docker CLI 管理本任务临时验收容器。**明确允许在本任务临时 Docker
  PostgreSQL 容器内创建隔离恢复数据库**，用于加密备份恢复与一致性验证；
  这是对“建库须单独授权”的限定批准，不允许在本机或共享实例新建数据库。
- 成功、失败或中断后清理本任务创建的夹具、临时服务、容器、备份、
  密钥和临时配置，恢复原配置；不得清理归属不明或非本任务资源。
  清理备份和密钥前确认恢复已完成或不再需要，保留必要回滚材料、
  发布签名验证所需材料及验收证据，不删除仍用于恢复的唯一副本。

## 执行规则

上述范围是持续授权，不随换工具、失败重试、版本号、候选哈希、提交信息、
OpenSpec 阶段或验收阶段变化而失效。执行前报告实质范围与风险即可，
不得再输出“请批准下一阶段”“批准一次性候选闭环”等整批授权请求，
也不得让用户复述固定口令。临时夹具更新或缺陷修复后的必要复验在范围内。

此前单批次的“不提交”等限制只约束原批次，不能覆盖本次更新的持续授权；
后续用户针对某批次新增的限制仍须遵守。HOST-003 文档保留其历史批准证据，
不将其限于单次 inspect 的范围误当成当前全部授权上限。

连接现有数据库、读取业务恢复状态及必要数据库身份/结构指纹属于上述验收；
不另做 PostgreSQL 服务状态巡检，不启动或重启本机 PostgreSQL。
仍不推送、不公开发布、不部署生产，不删除无关数据或修改无关项目。

系统沙箱、工具强制审批及硬拒绝保持有效。确需系统权限时，准确引用
本持续授权及具体动作走正式审批入口，不先向用户重复申请业务授权，
不以改命令、换工具或其他执行入口绕过拒绝。范围不明时先检查代码、
目标与资源归属；本文件不能作为越界操作的批准。

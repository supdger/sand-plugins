## Purpose

为插件作者提供明确最低宿主版本及可选最高版本的声明方式，使管理员页面、普通安装与升级操作能够作出一致且可验证的兼容决定；不兼容包在依赖、数据库和运行载荷变化之前被拒绝。

## ADDED Requirements

### Requirement: 声明包含边界的宿主版本范围

系统 SHALL 接受主版本通配符、次版本通配符、包含最低稳定版本及可选包含最高稳定版本的支持声明，并接受由 `|` 连接的分支并集。没有最高版本时系统 MUST 不隐式添加主版本上界。

#### Scenario: 最低版本边界
- **WHEN** 支持声明为 `>=0.1.0`，宿主分别为 `0.0.9`、`0.1.0`、`0.1.2`、`1.0.0`
- **THEN** 系统仅拒绝 `0.0.9`，其余三个宿主均满足声明

#### Scenario: 可选最高版本边界
- **WHEN** 支持声明为 `>=0.1.0 <=0.2.0`
- **THEN** 系统接受 `0.1.0` 和 `0.2.0`，拒绝 `0.0.9`、`0.2.1` 与 `1.0.0`

#### Scenario: 历史兼容语义
- **WHEN** 支持声明为 `6.x|7.x` 或 `0.1.x`
- **THEN** 系统分别接受对应主版本或次版本的合法宿主，且不会把 `6.x` 重解释成 `0.1.x`

### Requirement: 非法版本声明拒绝放行

系统 MUST 对缺失或非法宿主版本、非法支持表达式、上下界倒置及含非法分支的并集拒绝放行；宿主 build 信息不影响范围结果，同核心 prerelease 小于稳定版本。

#### Scenario: 并集中含非法分支
- **WHEN** 宿主为 `0.1.2`，支持声明为 `0.1.x|garbage`
- **THEN** 系统拒绝此声明，不能因为合法分支命中而接受

#### Scenario: prerelease 与 build
- **WHEN** 声明为 `>=0.1.0`
- **THEN** 系统拒绝 `0.1.0-rc.1`，接受 `0.1.1-rc.1` 和 `0.1.0+build.01`

### Requirement: 安装前强制兼容检查

系统 SHALL 在管理员页面和后端使用一致的版本兼容判断；普通安装或升级 MUST 在执行插件依赖、数据库脚本或部署运行载荷之前拒绝不兼容候选，并给出业务错误。

#### Scenario: 绕过前端直接安装
- **WHEN** 调用后端安装不满足宿主版本范围的候选
- **THEN** 系统拒绝操作，候选文件不变，不运行依赖处理和数据库脚本

#### Scenario: 已有升级检查保留
- **WHEN** Legacy 升级候选携带最低版本声明
- **THEN** 系统按照同一声明语义判断宿主，不删除既有升级前拒绝行为

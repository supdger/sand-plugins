## Why

用户实测无法仅凭 IAM 的首次引导和说明判断该填什么、从哪里取得值，登记完成也无法继续完成登录、权限和服务调用。两轮审计确认八类任务断点，需要在现有能力内补齐输入来源、连续操作和可观察结果。

## What Changes

- 首次登记后按所选应用继续“员工登录”“员工权限”“后端服务调用”，保留客户主体、应用和环境上下文；记录存在与实际使用成功分开显示。
- 解释应用用户记录与可登录账号的关系，串起认证设置、邀请、设密、登录入口和验证；不把后台新增用户记录说成已经开通密码登录。
- 为业务资源、动作、条件、数据范围和服务受众提供来自接入开发者或服务提供方的输入来源及中立示例；不自动生成未经应用确认的部门规则。
- 修正具体校验/冲突提示，保留安全错误边界；补充新建归属和一次性凭证归属摘要。
- 同步受影响管理员/员工/开发接入文档及 Wiki 草稿，提供登录取令牌和系统调用完整路径。
- 固定数据库与 SandAI 消费契约不变，核对当前锁定包、版本与升级来源，不升级测试宿主。

## Capabilities

### New Capabilities

- `iam-first-use-usability`: 首次登记后的连续任务、输入来源、上下文与可信完成状态。
- `iam-upgrade-compatibility`: 本次可用性优化保持既有数据与服务消费契约，明确版本和升级验证边界。

### Modified Capabilities

无。当前 OpenSpec 没有已登记规格；保留现有 SandIAM 产品需求和产品体验约束。

## Impact

- 产品修改限 SandIAM 权威管理端 Vue/TS、必要 helper 行为测试及受影响文档；OpenSpec 是本变更唯一任务来源。
- 不修改表结构、迁移、生命周期 SQL、机器字段名、路由协议、运行授权/签名/令牌安全校验、SDK 或 SandAI 产品源码。
- SandAI 当前 config.json 精确锁定 IAM 0.7.5 与包摘要；本地 IAM 源码 metadata 显示 0.7.3。发布前必须核对真实包基线，不用 0.7.3 替代或降级 0.7.5。
- 本次源码整改不代表包发行、宿主升级、真实登录/业务调用或生产验证已通过。

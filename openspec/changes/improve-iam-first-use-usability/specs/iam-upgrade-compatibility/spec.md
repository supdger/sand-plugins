## Purpose

约束本次 IAM 用户可用性优化的兼容边界，让已安装应用的身份、凭证和服务授权事实继续有效，保持 SandAI 的公开调用契约并明确源码检查、发行来源与真实平滑升级各自可证明的范围。

## ADDED Requirements

### Requirement: COMPAT-01 既有数据和机器契约保持
本次优化 MUST 不增加或修改表结构、迁移与生命周期 SQL，不改变机器字段、已有代码/标识、SDK 接口、签名令牌、安全校验和服务授权运行契约；既有数据不需重录或重发凭证。

#### Scenario: 已有 SandAI 消费 IAM
- **WHEN** SandAI 通过现有身份、引用验证、服务目录和调用授权契约运行
- **THEN** 本次管理端及说明优化不改变这些契约的参数、返回字段类型、服务代码、受众和拒绝规则。

### Requirement: COMPAT-02 版本来源可核验
升级说明 MUST 区分源码 metadata、依赖锁定版本、包摘要与有效安装路径；优化后的版本不得用旧 metadata 包降级已锁定的新版本，亦不得以版本号相同证明负载一致。

#### Scenario: 源码与 SandAI 锁定版本不一致
- **WHEN** 源码显示 0.7.3 而 SandAI 锁定 0.7.5 和特定包摘要
- **THEN** 报告差异并先核验对应包及 runtime/SQL 基线；发布或宿主升级继续保留明确未验证状态，不修改 SandAI 锁定配置以绕过核验。

### Requirement: COMPAT-03 升级验收诚实分层
本次交付 MUST 分开报告无数据库源差异、离线消费契约回归、真实已安装调用和备份后升级验证；静态与离线检查不可宣称已完成宿主平滑升级。

#### Scenario: 只完成源码和离线回归
- **WHEN** 本次未安装候选或未执行真实升级
- **THEN** 只报告已验证的源码和契约结果，说明真实升级及原数据/凭证/授权/审计验证缺口。

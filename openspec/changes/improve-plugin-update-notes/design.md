## Context

见 proposal.md 的问题与范围。现有 document API 读取 README，目录 notes 允许空字符串；三份 CHANGELOG 缺失，Core 与 Package 通过 Composer 分发，业务插件通过 ZIP 分发。当前工作区存在大量其他任务差异，需保留原编辑。

## Goals / Non-Goals

**Goals:** 管理员从源码首页或版本详情找到所选版本的更新内容，理解升级影响；维护者打包时默认生成对应版本说明。

**Non-Goals:** 不回填未知历史，不发布新版本，不修改数据库、宿主或服务，不让日志存在冒充业务验收。

## Decisions

- 五个单元根目录维护 CHANGELOG.md；README 靠前设独立“版本更新”栏目，以中文 Wiki 更新页、完整日志和持续发行入口帮助读者定位，详细使用教程继续链接既有 Wiki。Core 历史复用已缓存的权威公开 tag 日志；AI 候选仅写当前 README 和迁移可证的变化；Workflow 采用标签内原发行说明与明确修复提交。发布日期未获得证据则省略。
- document 增加可选 type=readme|changelog，缺省保持 readme；changelog 只读取经过既有 SHA-256 校验的所选版本 ZIP 根文件。不读取最新分支替代旧版本包，不修改既有下载安全边界。
- 构建器将根 CHANGELOG.md 带入 ZIP；匹配 info.ini 的版本标题，仅提取该章节，排除 Unreleased 和其他版本。显式 --notes 覆盖默认提取；缺失匹配时保留空值，不自动把未发布条目分配给发布版本。
- 版本详情保留已有 notes，空值说明缺口，并提供更新日志入口；旧包缺日志时清楚提示“该版本发布包未提供更新日志”。

### 更新发现路径的补充决定（2026-10-03）

- 用户反馈仅放行内 CHANGELOG 链接不可发现，Wiki 也没有明确更新入口。使用者为准备升级的管理员，只需知道组件名称；成功结果是从 README 或 Wiki 首页/侧栏一次导航找到最近公开版本正文及升级影响，再找到完整历史，无需理解英文文件名。
- 当前公开状态逐仓只读核实；Core 0.1.9、Package 稳定 0.1.9 / 公开预发布 0.1.10-rc.1、AI 0.1.0 preview 与本地统一包候选分别标注。独立公开仓的文档候选只叠加本轮导航/日志，不复制本仓 dirty 产品代码或未发布教程。
- Core、Package、AI 的独立 .wiki.git 当前均不可读取；沿用已存在的 SandAdmin Wiki，新建单一 plugin-updates 页。首页、侧栏、已有宿主 changelog 页连接该页；IAM、Workflow 使用各自现有 Wiki 的 Changelog。新 Wiki 页发布前链接只在候选中可用，不能宣称公开入口已修好。
- 本仓保留源码候选完整日志；AI 公开仓新增日志只记录可证的公开预览基线，Wiki 的完整公开历史先连接已存在 Releases，不指向公开 main 暂不存在的日志。

## Risks / Trade-offs

- [旧包没有日志] → 明确缺失，保留 README 默认路径，不伪造旧版内容。
- [版本标题与元数据不匹配] → 自动提取为空，可显式提供说明；用本地边界测试证明不提取错误版本。
- [源码候选被当作正式版本] → 候选标题明确状态，根入口说明源码记录与宿主升级验收的边界。
- [公开接口暂不可达] → 使用可核实的本地标签和现有发行记录，不宣称本轮已重新核对线上资产。

## Migration Plan

仅编辑权威源码与本地规格；对日志入口做静态核对，对 API/构建逻辑做必要本地回归，对新增版本详情路径做独立验收。提交、打包发布和宿主消费需另行在相应授权范围执行。回退仅撤销本轮差异，不覆盖其他任务编辑。

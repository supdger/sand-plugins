## Purpose

让首次安装 SandAdmin 的管理员在数据库初始化成功后，能够确认后台入口是否可访问；当独立前端未运行或部署入口配置不同，保留已完成的安装结果并获得可执行恢复步骤，通过重新检查进入真实后台登录页面。

## ADDED Requirements

### Requirement: 安装完成与后台就绪分别确认
系统 SHALL 在完成页保留成功结果与初始登录凭据，并检查后台专属静态资源响应；检查失败或超时 MUST 保留完成页、说明检查结果并允许重新检查，不得直接导航至不可访问地址。

#### Scenario: 前端未运行
- **WHEN** 数据库初始化成功但目标前端没有监听
- **THEN** 用户仍在完成页看到安装成功、后台尚未确认可用及恢复步骤，点击入口不会被直接送到连接拒绝页

#### Scenario: 前端启动后恢复
- **WHEN** 用户按恢复步骤启动前端并重新检查
- **THEN** 页面仅确认管理端静态资源已响应，并允许进入实际后台登录页面，原数据库不被重新初始化

### Requirement: 开发与部署入口具有明确配置来源
系统 SHALL 兼容已有开发端口配置，并支持显式同源路径或HTTP(S)后台公开URL用于部署；显式URL优先于开发端口，禁止把非法协议解释为可访问后台入口。

#### Scenario: 自定义开发端口
- **WHEN** 用户通过现有前端环境配置改变监听端口
- **THEN** 完成页使用该实际配置入口进行检查和进入，不回退到固定3006

#### Scenario: 明确部署地址
- **WHEN** 用户配置独立域名、HTTPS或子路径后台公开URL
- **THEN** 完成页使用该明确入口，不附加默认开发端口且不误导用户启动开发服务器

#### Scenario: 非法入口配置
- **WHEN** 配置使用脚本协议或格式无效的公开URL
- **THEN** 系统拒绝该入口并显示配置恢复信息，不能执行脚本或跳到猜测地址

### Requirement: 恢复操作不重复安装
系统 MUST 提供当前使用模式适用的恢复步骤、目标地址及检查反馈，并保持原数据库、管理员账号和登录鉴权契约。

#### Scenario: 后台检查失败后反复重检
- **WHEN** 用户多次检查尚未可达的后台入口
- **THEN** 页面不执行数据库初始化、迁移或重置密码，成功结果和恢复入口仍可查看

### Requirement: 已安装实例能够恢复后台入口
系统 SHALL 在安装后重新访问安装入口时提供后台访问检查与恢复，不重放初始密码；开发端口占用 MUST 明确失败，不能静默切换到完成页不知道的端口。

#### Scenario: 完成页刷新后恢复
- **WHEN** 已安装实例刷新或重新打开安装入口
- **THEN** 页面仍能检查和恢复后台入口，不能以重新安装作为恢复步骤，原数据库和凭据不变

#### Scenario: 开发端口被占用
- **WHEN** 配置的开发端口被其他服务占用
- **THEN** 前端启动明确报告端口占用，完成页检查结果仅表示专属静态标记响应，不把普通HTML或错误图像误判为通过

#### Scenario: 探测不改变登录状态
- **WHEN** 完成页执行后台入口探测
- **THEN** 探测不读取或写入登录token、不调用需身份的业务接口，不执行前端应用；结果仅表示管理端静态资源已响应，不能推定登录或业务正常，实际登录另行完成

#### Scenario: 网络策略阻挡检查
- **WHEN** HTTPS混合内容或生产CSP阻止检查静态标记
- **THEN** 页面说明当前无法确认而非断言前端未启动，保持完成页；另行明确标注尚未确认的手工专家出口，仅供用户主动选择，不自动导航

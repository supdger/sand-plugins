### 2. 复用与移植

先消费本地 SandAdmin 的 Controller/Permission/ApiException、Think ORM/事务、页面表格和表单；`ApiException` 显式 400/401，带稳定 `SAND_LICENSE_*` 错误标识。不引入 Laravel 框架。

研究已固定 `masterix21/laravel-licensing` 2.2.1，commit `d304d1cbaa50624bd0731a61500658936cbb7f62`：移植 `src/Services/UsageRegistrarService.php` 的事务锁许可→找安装→同安装活动更新→席位上限→受控复用释放席位流程，落入 `Logic/ActivationLogic.php` 和 `LicensingLogic::registerLocked`；移植 `src/Services/PasetoTokenService.php` 的刷新时重读许可/安装事实后重签流程，落入 `Logic/LeaseLogic.php` 和 `LicensingLogic::leaseLocked`。上游签发未显式核对 isUsable/isActive，本地状态与有效时间窗检查为必要补强，不归为上游已提供保障；替换签名为 Firebase，不搬 CA/PASETO、未验证的替换fallback和缺生效窗key查询。`laravelcm/laravel-subscriptions` 1.8.0，commit `68bf992aff33633659aa34ef85d705ba3c074e68`：`src/Models/Plan.php` 的功能/周期和 `src/Models/Subscription.php` 的有效期/续期/期末取消流程改造到 `Logic/PlanLogic.php`、`Logic/MembershipLogic.php`；不照搬用量read-modify-write或续期清空原周期/from-now算法。UTC期限使用原生 DateTimeImmutable，月末截断为本地补强，不声称移植上游 Period 的 Carbon 月溢出算法，不为研究文件数量凑额外移植。本插件按冻结UTC周期和独立grant改造，移植而非仅列链接。商业事件、领取和退款tombstone为现有组件未覆盖契约补实现。NOTICE记录实际四个业务出处的版本、SHA、原路径→改造路径；MIT完整许可随包，masterix Copyright(c)Luca Longo <l.longo@ambita.it>，laravelcm Copyright(c)2016-2021,Rinvex LLC。

能力选择宿主优先，同类沿用宿主现有实现。JWT由宿主既有`tinywan/jwt`及其传递依赖`firebase/php-jwt`提供，不在SandLicense单独require、lock或bundle JWT，不启用缺依赖fallback新栈，不更改Tinywan登录配置。Tinywan登录高层固定登录session和全局配置，不适合许可证独立受众/claims/keys；因此通过同一既有底层Firebase的公开JWT/Key/JWK API做许可薄适配，而非另选JWT作者或再造认证系统。实际使用EdDSA sodium detached签验与OKP/Ed25519公钥处理，独立许可claims和外部密钥不污染宿主登录。

运行兼容检查依据Tinywan官方Firebase约束`^6.8 || ^7.0`，还须验证必要JWT/Key/JWK公开API及EdDSA能力；缺Tinywan/Firebase、版本不兼容或能力不足均明确失败关闭。官方范围是候选兼容范围，不等于本项目全矩阵已测；本轮实际已验仅宿主Tinywan1.15.0/Firebase7.1.1。研究Firebase7.1.1 commit`9bc93bd7e3ee5bead4cd23c365ec12f3c1fb0a6a`用于精确源码证据，不变成插件独立锁定依赖。测试检查真实class来自宿主既有vendor、真实EdDSA签验，以及无宿主能力/不兼容明确拒绝；不再要求无宿主vendor成功。旧独立bundle方案及其成功证据仅为被替换的历史候选。

薄封装强制全部claims、固定alg/kid/issuer/audience/产品/权益/安装、公钥thumbprint及iat<=now、时间顺序；库存在nbf时不强制future iat，不能仅decode即认定许可有效。禁止修改JWT timestamp/leeway静态全局或任何宿主vendor，正式签名不用自制JWS/PASETO。私钥仅由受限配置引用，单测进程内临时密钥，不更改实际密钥。

### 3. PostgreSQL schema 冻结

主键统一 `bigint GENERATED BY DEFAULT AS IDENTITY`；本插件 FK 同类型、具名约束。配置记录含 `status` 1/2、`created_by`、`updated_by`、`create_time`、`update_time`、`delete_time`；业务状态用字符串 `state`。追加事件不软删、不用 status。所有时间以 UTC 写入 `timestamp(0) without time zone`，接口 ISO8601 UTC；JWT 用整数 UTC 秒。组织/应用/环境只保留 SandIAM 验证后的稳定引用，不复制用户或凭证表。跨插件引用不擅自建 FK 到未冻结身份主键。

| 表 sand_license_ 后缀 | 冻结主要字段与约束 |
| --- | --- |
| `product` | organization_id、application_id、code、name、audience、state(draft/published)、published_time、status；code 全局唯一，公开接口仅凭product_code仍无跨组织歧义；发布后organization_id/application_id/code/audience不变，管理读与退款释放不因停售失效；草稿应用关联通过正式IAM应用存在/权限/同组织校验，不靠单纯ID解析 |
| `plan` | product_id、code、revision、kind(desktop/membership)、duration_unit(day/month/year)、duration_value>0、seat_limit>=1 默认1、features jsonb；product/code/revision 唯一，发布快照不可变 |
| `sku_mapping` | product_id、plan_id、channel_code、sku_code；组织/产品/channel/sku 唯一，仅服务端映射套餐 |

| `challenge` | product_id、purpose、installation_key_thumbprint、secret_hash、state、expire_time、consumed_time；secret_hash 唯一，短时一次消耗 |

订单数量按单位拆领取资格，每一单位兑换只产生一个 desktop entitlement；会员 quantity 首期只接受1，避免默默将数量换算周期。没有渠道订单时手工来源 code 由服务端生成稳定值。退款可早于 paid 创建 fulfillment tombstone；其可信产品/channel/商品键由已配置渠道及 SKU 核对，不因乱序缺套餐随意写权益。

索引覆盖组织/产品、来源键、主体、未过期租约与事件时间；CHECK 覆盖期限>0、席位>=1、区间 start<expire、quantity>0、合法状态。席位并发不能只靠唯一 activation：兑换/激活/续签/释放持有同一 entitlement 行锁；首次创建先持码锁，取 entitlement 后固定 entitlement→activation→lease 顺序。履约持商业来源锁，事件+来源+grant/claim 在同事务落地；首次来源竞争由 UNIQUE+冲突重读统一处理，不靠进程内锁。

管理配置save/publish固定产品→套餐/SKU锁序：先scope受限但不加锁的hint确定原product_id，再锁原产品、重读并锁目标记录，核对product_id未变化并禁止客户端移动产品。履约与领取兑换固定产品→来源→claim→code→entitlement，产品锁须早于INSERT来源/新码触发的外键隐式KEY SHARE；新paid在来源后按产品→套餐顺序校验冻结版本。非锁hint仅定位关联，取得各行锁后重核产品/来源/claim/currentcode绑定。手工码无来源，维持产品→code→entitlement。退款、撤码及释放不因停售被当前销售gate阻断；首次发码/paid/兑换的销售gate保持原义。现用Think事务入口仅失败回滚后抛出，没有自动死锁重试；修复不能靠未证明的默认重试。本地源顺序检查与归属policy只能确认实现形状，实际PostgreSQL并发/死锁门仍须另行验收。

标准安装同时登记宿主共享 `sand_system_menu`（不是新建业务表）：根 code=`SandLicense`、path=`/plugin/sand-license`；九个 type=2 页面分别为 product、plan、code、entitlement、activation、sku-mapping、fulfillment、membership、event，path 为资源段，component 为 `/plugin/sand-license/<资源>/index`，code 为 `SandLicenseProduct/Plan/Code/Entitlement/Activation/SkuMapping/Fulfillment/Membership/Event`，page slug 为空，列表按钮 slug 沿用 `sand_license:<资源>:index`（sku-mapping 权限段为 sku_mapping）。前端薄页面固定资源并共享本插件列表组件，宿主负责导航、面包屑和页面框架，禁止再用页内横向模块标签替代菜单。

### 4. 首兑、租约与席位

码的产品/套餐事实由服务端查出，客户端 product_code 仅候选。首次成功兑换在事务内同时消耗 challenge、标记码 redeemed、创建 entitlement/grant、安装和租约；请求摘要相同的幂等重试返回原结果引用而非再发权益。UTC 首兑为起算点；day 为确定天数，month/year 使用目标年月末截断（1月31日+1月为2月最后一日、闰年2月29日+1年为次年2月末），保留 UTC 时分秒，禁止 strtotime 的月溢出。

challenge 120秒、iat 窗口60秒，jti/nonce 一次使用；安装 proof 使用 Firebase 验证 EdDSA JWS，header `typ=sand-license-proof+jwt`、`alg=EdDSA`，必填七项claims `htm`(大写HTTP method)、`htu`(配置的可信绝对URL，无query/fragment)、`iat`、`jti`、`nonce`、`body_sha256`(原始HTTP body字节SHA256)、`product_code`。proof放独立 `Sand-License-Proof` header，不把proof放body形成摘要循环；公钥由challenge绑定的安装thumbprint选取，不信任proof头自报key。nonce对应challenge只消耗一次，jti去重；purpose保存在服务端challenge(redeem/renew/current/release/enroll/ticket)，Logic核对用途与当前已路由端点，不另加JWT claim。安装协议统一POST JSON，包括`/entitlements/current`；activation_id/product_code/challenge/request_id等完整参数在JSON body，由原始body摘要签名绑定，不放nonce到URL query；无旧GET兼容。它是本产品安装持有证明，不宣称完整RFC DPoP、不新建workload credential。URI使用配置origin而非Host/X-Forwarded头，来源IP来自宿主可信入口。

JWT header `typ=JWT/alg=EdDSA/kid`，载荷必填 `iss/aud/sub/jti/iat/nbf/exp/product_code/entitlement_id/activation_id/cnf.jkt/features/plan_revision`；sub=entitlement_id十进制字符串，不引入license_id同义字段，所有ID字符串。exp=min(now+900,权益到期)，建议 renewal_after=300。启动必须向在线端取得新租约，缓存只允许当前运行继续到 exp；每次在线敏感调用重读领域撤权状态。时钟容差不得把授权运行延长到 exp 之后，必须验证iat不未来、nbf<=iat<=exp以及有配置产品受众。

签名层冻结在 `Security/LeaseToken.php`：构造 `(string kid,string privateKeyBase64,array publicKeysByKid,string issuer)`；`issue(array domainClaims,int entitlementExpire,int now):string`，domainClaims必含aud/sub/entitlement_id/activation_id/product_code/plan_revision/features/cnf.jkt/jti；`verify(string token,string expectedAudience,string expectedProductCode,string expectedEntitlementId,string expectedActivationId,string expectedJkt,int now):array`。`Security/InstallationProof.php`：`thumbprint(array OKPJwk):string`；`verify(string proof,array OKPJwk,string method,string configuredAbsoluteUrl,string rawBody,string nonce,string productCode,int now):array`。`Security/Challenge.php`：`issue(int now):array{nonce:string,secret_hash:string,expire_time:int}`、`digest(string nonce):string`。这些工具不访问DB；nonce消费和proof jti唯一由Logic事务实现。proof在API表仅简写，传输总在独立header。

release/reset 立即禁止旧安装续签，撤销服务端 lease 记录；无法收回已发本地令牌，席位因此冻结至该安装最后签发 exp，页面返回 seat_available_time。新安装不能提前重用该席位，reset不缩短冻结期。release的明确 `issue_enrollment_ticket=true` 或有权管理员操作签发新设备资格，仅HMAC持久保存并一次展示；参数必须为JSON布尔且默认false，进入同一幂等业务摘要，不接受字符串或数组强制转换。响应丢失可明确撤销尚未消费ticket再签，普通重试返回状态；已释放安装只可恢复source_activation_id明确等于自身的换机票，source_activation_id为空的额外团队票需要活动安装，授权检查先于撤销旧票。新设备通过ticket+新安装challenge/proof进行enroll，available_time前拒绝、消费一次、只加安装不再次发权益。团队额外ticket也必须持权益行锁核对seat_limit，不能承诺绕上限；原已兑卡密不作日常renew或换设备secret。

current、renew和其他安装许可敏感重试必须先读取并验证当前权益/安装状态，持久幂等结果不作有效授权来源。current从不返回历史active/features，合法新challenge/proof再次读取实时事实并消费nonce/jti，不因同request_id重复插入幂等记录；已消费proof不得再作为新的current调用。普通renew重试只返回脱敏引用，不复签令牌，且已释放、撤权或到期必须失败。

### 5. API 与授权冻结

运行前缀 `/api/sand-license/v1`，管理前缀 `/app/sand-license/admin`，自助页面 `/license/claim`。管理响应沿宿主壳，`@/utils/http`解包；列表 `Api.Common.ApiPage<T>={current_page,per_page,total,data}`，禁止额外data套娃，返回product_name/plan_name可读列。所有ID十进制字符串、时间`*_time`为ISO UTC并附server_time，稳定state和业务提示。管理发码request_id必填并可查状态；同request重试仅返回status+code_id，不重放明码，未兑换可明确重签。公开响应 data 保持相同类型。拒绝无卡密存在性细节，秘密不进入 URL/query、日志、dedup、事件或默认列表。领取页面NoStore/NoReferrer，凭证由URL fragment转POST；运行错误用精确稳定错误码与400/401。

| --- | --- |

### 5.1 执行者共用Logic调用形状

沿用 `think\facade\Db` 及现有事务，不创建通用Repository平台。由HTTP边界完成验证、构造可信scope，再调用下列array输入；域方法自行重读持锁行防TOCTOU。运行scope含 `organization_id/application_id/environment_id` 的已验证引用和受限 `product_id`、`actor_ref/request_id`，不能将原始客户端header作为scope；管理scope为实际AdminOrganizationAccess解析的organization_ids列表，或仅真实is_super_admin=true时的null全域，空列表从不视为超级管理员。每个public写方法input必含request_id，返回server_time ISO UTC；原始body/proof只放request参数，不进事件或dedup。

- `CodeLogic::__construct(string pepper)`；`issue(array input,array scope,int now):array`：input={product_id,plan_id,request_id,expire_time?}，返回{state,code_id,code?仅首次,prefix,request_id,server_time}。`status(string requestId,array scope,int now):array`无明码；`reissue(string codeId,string requestId,array scope,int now):array`仅未兑。`issueForClaimLocked(array claim,array product,array plan,int now):array`要求调用者已持claim事务锁，返回{code_id,code,prefix}，不另开事务。`generateSecret():string`、`hashSecret(string secret):string`使用PHP成熟random_bytes/hash_hmac，由此类独占；履约领取凭证复用这两个方法，不重复实现HMAC。
- `LicensingLogic::__construct(?CodeLogic codes,?Security\LeaseToken tokens,Security\InstallationProof proofs,string configuredOrigin)`；只有需要HMAC或签发的方法才要求对应配置，不以缺私钥阻断管理草稿、读取或challenge。`challenge(array input,int now):array`：input={product_code,purpose,installation_public_key}，返回{challenge,expire_time,server_time}。`redeem/renew/current/release/enroll/ticket(array input,array request,int now):array`；request={method,configured_url,raw_body,proof}，origin由构造配置限定，method/path由可信路由限定。redeem input={product_code,code,installation_public_key,name?,challenge,request_id}；renew/current/release input={product_code,activation_id,challenge,request_id,issue_enrollment_ticket?}；enroll input={product_code,enrollment_ticket,installation_public_key,name?,challenge,request_id}；ticket input={product_code,entitlement_id,activation_id,challenge,request_id,reissue_ticket_id?}。返回{state,entitlement_id,activation_id?,lease?,expire_time?,renewal_after?,seat_available_time?,ticket_id?,enrollment_ticket?仅首次,request_id,server_time}。current另外返回features/plan_name/seat_limit/used_seats，不回卡密。
- `FulfillmentLogic::__construct(CodeLogic codes,MembershipLogic memberships,int claimTtlSeconds=2592000)`；TTL可配3600..31536000秒。`ingest(array input,array scope,int now):array`：input为events API表形状加product_code/request_id及refund_kind(full/partial)，返回{state,fulfillment_id,claim_ids,entitlement_id?,request_id,server_time}，首次资格一次返回claim_credentials:list<{claim_id,claim_credential}>，重试仅status/id。`refreshClaimCredential(string claimId,array input,array scope,int now):array`：input含request_id；可信显式重签撤旧凭证、清会话绑定，已兑/退款/过期拒绝，不新增码或权益，明凭证仅首次展示。`read(string fulfillmentId,array scope,int now):array`脱敏；`status/claim/reissue(string claimId,array input,int now):array`：input={claim_credential,session_key,request_id}，返回{state,claim_id,code_id?,code?仅首次或显式重签,prefix?,request_id,server_time}，status永不返回明码，自助必须明确reissue路由。产品范围从claim关联事实解析而非请求自报。
- `MembershipLogic`无密钥构造；`applyPaidLocked(array fulfillment,array plan,int now):array`、`revokeSourceLocked(array fulfillment,int now):array`、`cancelSourceLocked(array fulfillment,int now):array`由履约事务调用，返回{state,entitlement_id?,grant_id?}；`current(array input,array scope,int now):array`：input={product_code,subject_code}，返回{state,entitlement_id?,features,intervals:list<{start_time,expire_time}>,server_time}。区间存储字段为cycle_start_time/cycle_expire_time，HTTP同名；禁止把单独expire_time误作购买周期。构造不访问DB，取消仅cancelled_time，退款只来源grant。

管理层 `AdminLogic` 允许无secret构造，index/read/save/publish不加载签名配置；index消费page/limit、product_id/state、plan.kind和可读关键词，published产品才能新发码/新兑换/新付履约/新安装与续租。管理reset参数={activation_id,reason,request_id,issue_enrollment_ticket?}，默认false，界面明确勾选后才签ticket，由scope受限调用释放内核而不伪造旧安装proof。`LicensingLogic::reset(array input,array scope,int now):array`返回与release相同结果；`adminTicket(array input,array scope,int now):array`消费{entitlement_id,reason,request_id,reissue_ticket_id?}，经`POST /app/sand-license/admin/entitlement/ticket`和`sand_license:entitlement:ticket`签发团队/换机ticket，仍同权益锁和席位上限，保留available_time，不新增grant。方法名称和字段须由各执行者保持一致，发现修改先交主控协调。

设备列表/详情投影保留调用者原管理scope，沿activation.entitlement_id→真实entitlement.product_id并经既有ProductLogic::scoped重核组织/产品范围后提供product_id/product_name；历史展示不要求产品仍在售，不能从请求自报产品替代关联。最新lease日期聚合使用Think max(expire_time, false)保留PostgreSQL timestamp，不采用默认数字强转或放宽Values时间校验。所有含设备的嵌套投影沿用同一scope、UTC转换及秘密剔除。

可信业务输入由正式 SandIAM `IdentityContextProvider::verifyForService` 验证服务 `sand_license`、audience、action、可信来源；使用 `ServiceInvocationAuthorizer::authorizeInvocation` 完成实际调用授权。`SandLicense` 本地实现 `ServiceInvocationFactResolver`，通过自有 `ServiceInvocationFactResolverRegistry` 注入 `sand_license.fulfillment`/`sand_license.membership` resolver，调用方 scope 与配置渠道、产品、主体资源核对；不改 SandIAM、不开新认证表、不接受 unsigned identity headers。缺正式端口/事实/可信上下文失败关闭。服务目录通过已有 ServiceCatalog 显式登记，并以既有授权入口配置 grant；不能在 install SQL 偷写身份授权事实。

管理动作：product/plan list/read/save/publish；code list/issue/revoke；entitlement list/read/suspend/revoke；activation list/read/release/reset；fulfillment list/read；membership list/read；event list/read。Permission 使用 `sand_license:<resource>:<action>`、宿主登录和组织/产品范围约束；按场景给敏感动作影响提示、理由、确认，禁止直接编辑 state。安装代码无需预建全能管理员。

### 6. 领取与会员来源安全

paid 只创建领取资格，生成码发生在 claim；卡密至少128位熵，HMAC lookup 使用受限 pepper，常数比较，持久化仅 prefix/secret_hash/pepper_version。ordinary claim retry 不重放丢失明码；显示“已领取，需要新码请重新签发”。reissue、领取凭证恢复、退款和claim关联redeem统一产品→来源→claim→code→entitlement协调锁，锁后重核关联且退款/chargeback来源禁止旧码首兑；与redeem互斥，竞争失败返回明确业务4xx而非SQL死锁内部错误。已兑换不再生成码或权益，既有retry另核实时权益/安装状态。claim 凭证本身一次交付，丢失由可信业务重新签发新凭证并撤销旧凭证，不持久化其明文。订单号或客户端自报买家不能授权领取。

membership 使用 product+业务 subject_code 归属，不生成卡密/安装；每来源独立entitlement+grant，不另建第二会员身份表。每个 paid 来源grant固定 [start,expire)；期限由可信支付周期输入验证，续期使用不同 payment_cycle_id，重叠区间允许并按有效grant并集判断。features仅当前有效来源参与，布尔OR、非负整数max，不实现新用量系统。退款/拒付只撤同来源；无有效grant才无会员权益，不能清整用户或移动其他周期。退款先到 tombstone、后 paid 不复活；无论到达时间/客户端时间。取消仅记录后续自动续期停止，不撤已有paid周期。v1仅精确定位全额来源退款；部分退款返回 `SAND_LICENSE_PARTIAL_REFUND_UNSUPPORTED` 并提示人工处理，禁止假成功或自动按金额换算天数。

### 7. 使用者与最小入口

运营从“商业许可”进入“软件产品/套餐与功能/卡密发放/已发放权益/设备激活/履约与会员/操作记录”，创建产品套餐、默认席位1，发布后发码并确认一次复制。客服查看掩码和状态，通过明确“重置设备”看到席位可用时间和影响。买家只需可信业务交付的领取链接，看到待领取/已领取/已兑换/过期/退款状态，明确重发不要求数据库术语。接入者从源码包 README→接口示例获得上下文/产品SKU来源及幂等/失败处理。无需源码和作者提示才能完成为 UI 验收目标。

## Risks / Trade-offs

- 已签本地JWT不可即时收回 → release/reset冻结至旧exp，在线API立即检查撤权，新启动在线取新令牌。
- HMAC不可恢复明码 → 普通重试返回状态、明确重签仅未兑码；凭证和日志最小化。
- 上游Laravel能力不满足乱序商业事件 → 保留可移植算法，来源锁/幂等/tombstone作为有证据缺口补实现。
- 初始源码阶段无DB与宿主执行授权 → 当时只以无DB测试验证领域行为；后续临时授权后仍须按SQL/真实安装/并发事务/页面分别取证，不能因授权已具备而勾选未实跑项。
- 上游源码只研究指定文件 → 实际移植映射、宿主既有依赖消费与真实签验分别记录证据，不以研究结论或旧bundle候选代替当前实现通过。

## Migration Plan

无旧系统迁移。初始阶段完成源码、无DB回归与包静态验证；用户随后已明确授权完整临时验收，使用冻结的任务临时宿主与唯一临时PostgreSQL目标，标准安装新插件并验收真实HTTP/事务/页面及恢复，允许隔离临时keys/fixtures、必要独立测试服务与本次新增临时资源清理。宿主/DB/服务setup由唯一执行者管理，不改持久业务库或既有keys，不把临时授权扩大到其他资源；仍不修改无关既有dirty。提交发布待相应授权、实际暂存审查与pre-commit接入核验；实际业务和UI证据按tasks逐层记录，不由安装成功或helper通过推导。

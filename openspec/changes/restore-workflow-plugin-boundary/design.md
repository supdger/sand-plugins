## Context

动机见 proposal.md。SandAdmin 已有仓库治理文档；sand_plugins 已有插件职责入口，当前无跨插件改造论证的统一入口。工作树存在其他在途变更，恢复须按文件及 hunk 确定归属。SandAI 当前 6.1 的消费端实现与规格由其现有 unify-sandai-product change 衔接。

## Goals / Non-Goals

**Goals:** 恢复提供方领域边界，使 SandAI 使用既有 Workflow 公开契约；两仓规则可发现且由 sand_plugins 保有同一论证来源。

**Non-Goals:** 新建通用异步引擎、替换现有权限体系、将规则包装为运行时拦截；本轮不因文档建立自动取得数据库或发布权限。

## Decisions

- 回滚仅针对 6.1 引入的专用改造及配合变更；以修改归属与版本证据识别，保留其他在途工作。整体重置会覆盖无关修改，不能采用。
- SandAI 消费端 start/detail 适配只处理调用方明确请求，显式接收经服务端认证与授权确认的可信 context；分析成功或 review_required 不自动发起流程、审批或其他业务动作。
- 原需求为材料服务独立运行，业务流程使用 SandWorkflow 调用已发布 SandAI 服务，并保留原幂等键找回不明响应、当前授权控制读取、来源费用追溯。start/detail 适配不等于这条完整业务链已实现；该业务链及上述恢复、权限与追溯行为由 unify-sandai-product 6.1 继续描述与验证，未完成则保持未完成。SERVICE=7、机器启动与双向通知属于此前实现选择，不能作为必须改造 Workflow 的依据。
- sand_plugins 的 docs/cross-plugin-changes.md 是短规则的权威位置；AGENTS 链接该页。SandAdmin 使用薄入口和现有治理页摘要引用，避免维护两份详细规则。
- 通用性与必要性是可替代的论证路径，均须保持提供方领域边界；独立审查依现有编排规则，无额外用户审批口令。

## Risks / Trade-offs

- [已存在消费或数据] → 核实候选发布、实际副本和数据状态；源码恢复不隐式删除运行数据，实际迁移另按授权执行。
- [以文本通过冒充能力完成] → 分别记录规则边界审查、源码回归与真实宿主验收；缺失证据保留未完成。
- [工作树争用] → 固定候选的前后 SHA，应用前核对基线；不同变更不得覆盖。

## Migration Plan

先保存目标差异与候选基线，恢复已确认专用源码并调整消费者。规则候选经独立审查后精确应用并比对。必要宿主迁移、同步与部署另按明确授权处理，未实际执行时保留缺口。
